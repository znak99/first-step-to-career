# SITE_MAP

> 사용자가 설명한 iOS 모의면접 화면·기능의 요구사항이다. 실제 화면 분리, 표시 명칭, 배치, 탐색 구조와 로그인 사용 여부는 미정이다. 이 문서의 기능 명칭은 최종 일본어 UI 문구가 아니다.

## 1. 화면·기능 목록
| 화면·기능 | 확정된 요구사항 |
|---|---|
| 설정 등의 메뉴 | 질문 개수의 첫 사용 기본값은 5문이며, 3~7문으로 조절한다. |
| 시선·머리 채점 설정 | 설정 하나로 함께 켜고 끈다. 평가 가능한 기기의 첫 사용 기본값은 켜짐이다. 면접 시작 후에는 변경할 수 없으며 변경하려면 모의면접을 먼저 종료해야 한다. 조작 방식은 미정이다. |
| 모의면접 시작 | 회사명, 업종, 직무, 인사/직무 면접을 선택한다. |
| 준비 화면 | 관찰 거리·전면 카메라 동작·TrueDepth 지원·추적 가능 여부를 확인한다. 조명 등으로 추적이 어려우면 확인 메시지를 표시하고 시선·머리 평가를 모두 제외한다. |
| 면접 진행 | AI 질문의 음성 재생, 사용자 답변의 실시간 문자 표시, 답변 중 무음 3초와 종료 예고 타이머 애니메이션을 제공한다. 이어서 말하기는 다음 질문 준비·음성 재생 중에도 가능하며, 직전 답변을 이어서 받은 후 전체 답변으로 다음 질문을 다시 검토한다. 설정된 질문 개수만큼 반복한다. |
| 결과 확인 | 정상 완료한 면접의 종합평가 점수, 적용 항목별 점수, 질문·답변 스크립트를 표시한다. 제외된 시선·머리 항목에는 숫자 대신 평가 제외 상태와 이유를 표시한다. |
| 과거 모의면접 확인 | 휴대폰 내부에 저장된 과거 질문·답변 스크립트를 다시 볼 수 있다. 기록을 한 건씩 선택해 확인 후 삭제할 수 있다. |

### 1.1 질문 개수 기본값 승인 (2026-11-05)
사용자가 앱 첫 사용 시 질문 개수 기본값을 5문으로 두는 방식을 승인했다. 사용자는 설정 등의 메뉴에서 3~7문으로 변경할 수 있다. 설정 화면의 위치·조작 방식과 설정값 저장 방식은 미정이다. 설정 기능 구현이나 앱 시험은 수행하지 않았다.

## 2. 화면 간 흐름
1. 회사명·업종·직무·면접 종류 선택 → 준비 화면 진입
2. 거리·카메라/TrueDepth 지원·추적 가능 여부 확인. 조명 등으로 추적이 어려우면 확인 메시지와 두 움직임 항목 제외 적용 → 모의면접 진행
3. AI가 TTS(문자를 음성으로 읽는 기능)로 질문 → STT 시작 후 첫 단어 대기. 7초간 단어 미감지 시 재질문하고, 재질문 후 STT 시작부터 다시 7초간 단어 미감지 시 평가·점수 산출 없이 면접 종료
4. 사용자 답변을 STT(음성을 문자로 바꾸는 기능)로 화면에 표시 → 답변 중 무음 3초와 종료 예고 타이머 적용 → 다음 질문 준비·재생 중 이어서 말하기를 선택하면 이를 중단하고 직전 답변 재개 → 답변 완료 후 전체 답변으로 다음 질문 재검토
5. 다음 질문으로 이동하며 설정한 3~7문까지 반복 → 면접 종료. 이어서 말하기로 중단된 다음 질문은 문항 수에서 제외하고 다시 검토한 질문에 같은 번호를 사용
6. 답변 평가 완료 → 종합점수·항목별 점수·질문 및 답변 스크립트 확인

과거 기록에 진입하는 탐색 경로와 설정 메뉴 위치는 미정이다.

## 3. 준비 화면과 평가 제외 조건
- 시선과 머리 움직임을 정확히 관찰할 수 있는 거리인지 확인한다. 거리 기준과 안내 방식은 미정이다.
- 전면 카메라가 정상적으로 동작하지 않거나 기기가 TrueDepth를 지원하지 않으면 시선·머리 움직임을 모두 채점 항목과 종합점수에서 제외한다.
- 준비 화면에서 조명이나 다른 이유로 움직임 추적이 어려우면 확인 메시지를 표시하고 시선·머리 평가를 모두 제외한다. 상세 요구사항은 4.23을 따른다.
- 제외 항목은 0점으로 반영하지 않는다. 결과 화면에는 4.25와 같이 승인된 평가 제외 상태와 이유를 표시한다. 최종 일본어 문구·배치는 미정이다.
- 면접 도중 시선·머리 중 하나라도 정상 추적 자료를 3초 연속 얻지 못하면 4.24의 안내·두 항목 전체 제외·면접 계속 규칙을 적용한다. 3초 미만 누락은 4.26의 승인된 규칙을 따른다. 정상 자료의 판별 기준과 카메라·마이크 권한 거부 처리는 별도로 논의한다.

## 4. 면접 진행과 결과 확인
- 질문을 읽는 동안과 사용자가 답변하는 차례를 구분한다.
- STT가 새 발화에서 단어를 하나 이상 감지하면 말하기 시작으로 판단한다. 새 질문과 이어서 말하기 후의 첫 단어 대기는 모두 4.7의 7초 무응답 정책을 따르며, 단어 감지 이후에는 답변 중 무음 3초 기준을 적용한다.
- 답변 중에는 사용자의 말을 문자로 표시한다.
- 답변이 시작된 뒤 3초간 연속 무음이면 답변 종료로 판단한다. 화면에 종료까지 남은 시간을 타이머 애니메이션으로 표시하고, 사용자가 같은 답변을 이어갈 수 있도록 이어서 말하기 버튼을 제공한다.
- 시선·머리 움직임은 면접 시작부터 결과 표시 직전까지 전 구간을 채점하되 4.29의 종료 확인 창 표시 시간은 제외한다. 질문 준비·재생, 첫 단어 대기·재질문, 답변·무음·이어서 말하기와 면접 후 평가 대기도 포함한다. 지원되지 않는 경우에는 두 항목을 제외한다. 상세 범위는 4.17을 따른다.
- 정상 완료한 면접은 답변의 구성·논리력·현실성을 평가하고, 종합평가 점수·각 항목별 점수와 질문·답변 스크립트를 표시한다.
- 마지막 답변 이후 평가 중에도 이어서 말하기를 제공한다. 선택하면 평가를 중단하고 마지막 답변을 추가로 받은 뒤 전체 답변으로 다시 평가한다.
- 시선·머리 채점 설정을 변경하려면 진행 중인 모의면접을 먼저 종료해야 한다. 사용자 종료는 4.28의 승인된 확인 절차를 따른다. 확인 창 중 전체 정지·취소 후 재개는 4.29를 따른다. 조기 종료 후 화면 복귀는 4.33을 따른다. 별도 일시정지 기능·답변 수정·재시도 등은 아직 정하지 않았다.

### 4.1 무음 3초·종료 타이머·이어서 말하기 요구사항 (2026-11-05)
사용자가 답변 중 무음 기준을 3초로 지정했다. 마지막 발화가 끝난 뒤 3초 후 답변이 종료됨을 알 수 있도록 화면에 타이머 애니메이션을 표시한다. 사용자가 원하면 같은 질문의 답변을 이어갈 수 있도록 이어서 말하기 버튼을 제공한다. 이전의 미승인 7초 제안은 사용자가 지정한 3초로 대체했다.

3초 이후의 버튼 동작은 사용자가 추가로 지정한 4.2, 첫 발화 대기는 4.3을 따른다. 카운트다운 중 버튼 사용 여부, 타이머 모양·버튼 위치·최종 일본어 문구는 미정이다.

이 무음 기준은 STT가 새 발화에서 단어를 하나 이상 감지한 뒤에 적용한다. STT 단어 판별·중간/확정 결과 처리 방식과 무음 검출 방법, 인식 오류 처리는 미정이다. 타이머·버튼·음성 기능 구현이나 실제 동작 시험은 수행하지 않았다.

### 4.2 질문 준비·재생 중 이어서 말하기 동작 (2026-11-05)
사용자는 3초가 지난 뒤 LLM이 다음 질문을 생각하는 중이나 질문을 음성으로 읽는 중에도 이어서 말하기 버튼을 누를 수 있어야 한다고 지정했다. 버튼을 누르면 다음 흐름을 따른다.

1. 진행 중인 다음 질문 준비 또는 음성 재생을 중단한다.
2. 기존 답변을 유지한 채 직전 질문의 답변을 이어서 받는다.
3. 사용자의 이어진 답변이 완료된 뒤, 기존 답변과 추가 발화를 포함한 전체 답변을 바탕으로 다음 질문을 다시 검토하고 질문한다.

재개한 답변도 4.3의 STT 단어 감지로 발화 시작을 판단한 뒤 무음 3초 기준을 적용한다. 중단한 질문의 문항 수 처리는 4.4, 스크립트 보관은 [DATA.md](../system-design/DATA.md)의 1.5, 마지막 답변 평가 중 이어서 말하기는 4.5와 같이 승인받았다. 카운트다운 중 버튼 사용 여부는 미정이다. 취소·재개·질문 재검토 기능 구현이나 실제 동작 시험은 수행하지 않았다.

### 4.3 첫 발화 대기와 STT 단어 감지 기준 승인 (2026-11-05)
사용자는 "말을 시작했다"를 STT가 단어를 하나 이상 감지한 것으로 정의했다. 이 시작 조건은 유지하며, 단어 감지 이후에는 답변 중 무음 3초 기준을 적용한다. 당초 승인한 첫 단어 무제한 대기는 이후 사용자가 지정한 4.7의 무응답 7초 규칙으로 변경했다. 이어서 말하기 후에도 같은 7초 규칙을 적용하도록 사용자 승인을 받았다.

이어서 말하기를 누른 뒤에는 새로 이어 말한 발화의 단어 감지를 기다린다. 기존에 저장된 답변의 단어만으로는 이 대기를 끝내지 않는다. STT 단어 판별과 중간/확정 결과 처리의 구체적인 방법, 무음 검출과 인식 오류 처리는 미정이다. 구현이나 실제 음성 시험은 수행하지 않았다.

### 4.4 중단된 질문의 문항 수 처리 승인 (2026-11-05)
사용자가 이어서 말하기로 중단된 다음 질문은 문항 수에 포함하지 않고, 전체 답변으로 다시 검토한 질문을 같은 문항 번호로 제시하는 방식을 승인했다. 예를 들어 5문 설정에서 3번 질문을 준비·재생하다 중단했다면, 추가 답변을 받은 뒤 제시하는 질문도 3번으로 둔다. 최종 질문·전체 답변 보관과 중단된 질문의 스크립트 제외는 [DATA.md](../system-design/DATA.md)의 1.5와 같이 별도로 승인받았다. 문항 진행 코드 구현이나 실제 동작 시험은 수행하지 않았다.

### 4.5 마지막 답변 평가 중 이어서 말하기 승인 (2026-11-05)
사용자가 마지막 답변 이후 평가 중에도 이어서 말하기 버튼을 제공하는 방식을 승인했다. 선택하면 진행 중인 평가를 중단하고 마지막 답변을 이어서 받은 뒤, 보완된 전체 답변을 바탕으로 다시 평가한다. 재개한 발화는 STT가 새 발화에서 단어를 하나 이상 감지할 때 시작으로 판단한다. 시작 후에는 기존 무음 3초 기준을 적용하며, 재개 후 첫 단어 대기에도 4.7의 무응답 7초 정책을 적용한다.

승인 범위는 평가가 진행 중인 동안의 마지막 답변 재개와 재평가다. 결과 화면 표시 이후의 답변 재개 여부, 평가 취소·재실행과 관찰 자료 반영의 구체적인 구현은 미정이다. 시선·머리 채점 범위는 이후 4.17과 같이 면접 시작부터 결과 표시 직전까지 전 구간으로 지정됐으며 평가 대기와 답변 재개도 포함한다. 이후 4.29에 따라 종료 확인 창 표시 시간은 관찰·채점에서 제외한다. 앱 구현이나 실제 동작 시험은 수행하지 않았다.

### 4.6 점수 범위·소수점 사용 승인 (2026-11-05)
사용자가 적용되는 각 평가 항목과 종합점수의 0~100점 범위를 승인하고 소수점 사용을 지정했다. 표시 자릿수·반올림은 이후 4.10, 가중치·제외 항목 발생 시 환산은 4.12, 답변 3항목의 문항별 점수 통합은 4.13과 같이 승인받았다. 시선·머리의 구간 비율·감점량은 승인받았으며 실제 기준점·화면 좌표 판정과 보정은 미정이다. 카메라 오류 또는 TrueDepth 미지원 시 시선·머리 움직임을 채점과 종합점수에서 제외하는 기존 요구사항은 유지한다.

### 4.7 무응답 재질문·면접 종료 규칙 (2026-11-05)
1. STT 시작 후 7초 동안 새 단어가 하나도 감지되지 않으면 재질문한다.
2. 재질문 후 STT가 다시 시작되고 7초 동안 새 단어가 감지되지 않으면 면접을 종료한다.
3. 최신 4.30에 따라 이 자동 무응답 종료는 답변 평가·항목별/종합점수 산출·결과 점수 표시 없이 끝낸다.

이 규칙은 새 질문과 이어서 말하기 모두에 동일하게 적용하며, 마지막 답변 평가를 중단하고 이어서 말하는 경우도 포함한다. 단어 감지 이후의 답변 종료용 무음 3초와 첫 단어 대기용 7초는 구분한다. 종료 확인 창 표시 시간은 4.29에 따라 모든 시간 집계에서 제외한다.

이전의 미진행분 감점과 이어 말하기 실패 추가 감점은 4.30으로 대체했다. 재질문 문구·STT 오류/권한 문제와 실제 무응답의 구분은 미정이다. 조기 종료 기록은 이후 4.31에 따라 저장하지 않으며 조기 종료 후에는 4.33에 따라 모의면접 시작 화면으로 돌아간다. 이후 추가 승인을 받아 핵심 소스의 무응답 처리와 채점 API에도 무평가 정책을 반영했다. 실제 화면 이동은 미구현이다.

### 4.8 미진행분 기본 감점 계산 승인 (과거 결정, 4.30으로 대체)
> 적용 중단: 아래는 이전 승인 당시의 기록이다. 현재 중도·무응답 종료는 평가·점수 산출 없이 종료하며 이 계산과 예시를 사용하지 않는다. 현재 규칙은 4.30을 따른다.
사용자가 새 질문에 답변을 시작하지 못해 조기 종료한 경우의 다음 기본 감점 계산을 승인했다.

`최종 종합점수 = 감점 전 종합점수 × 완료 문항 수 ÷ 설정 문항 수`

- 감점 전 종합점수는 완료 문항을 바탕으로 산출한 0~100점의 품질 평가 점수이며, 여기에 완료 비율을 한 번 적용한다. 항목별 가중치와 제외 항목 발생 시 환산은 이후 4.12, 답변 3항목의 문항별 점수 통합은 4.13과 같이 승인받았다. 시선·머리의 구간 비율·감점량은 승인받았으며 실제 기준점·화면 좌표 판정과 보정은 미정이다.
- 항목별 점수는 품질 평가 점수로 표시하고, 미진행분 감점은 최종 종합점수에 반영한다. 적용 불가 시선·머리 항목을 제외하는 기존 요구사항은 유지한다.
- 예를 들어 설정 5문 중 3문 완료, 감점 전 종합점수 80점이면 최종 종합점수는 `80 × 3 ÷ 5 = 48점`이다.
- 완료 문항이 0개라 품질 평가 점수를 산출할 수 없는 경우에는 최종 종합점수를 0점으로 처리한다.

이어서 말하기 무응답 종료의 감점은 이후 4.9, 표시·반올림은 4.10, 완료 문항 인정 기준은 4.11과 같이 승인받았다. 실제 채점 구현과 시험은 수행하지 않았다.

### 4.9 이어서 말하기 무응답 종료의 감점 승인 (과거 결정, 4.30으로 대체)
> 적용 중단: 아래는 이전 승인 당시의 기록이다. 현재 중도·무응답 종료는 평가·점수 산출 없이 종료하며 이 계산과 예시를 사용하지 않는다. 현재 규칙은 4.30을 따른다.
사용자가 기존 답변이 있는 문항에서 이어서 말하기 후 7초 무응답·재질문 후 다시 7초 무응답으로 종료한 경우의 감점을 승인했다. 기존 답변과 그 문항의 완료 인정을 유지하고, 완료 비율 반영 후 종합점수에서 5점을 추가 감점한다.

`최종 종합점수 = max(0, 완료 문항 기준 감점 전 종합점수 × 완료 문항 수 ÷ 설정 문항 수 − 5)`

- 추가 감점은 이 무응답 종료 시 한 번 적용하는 5점이며, 최종 종합점수의 하한은 0점이다. 항목별 품질 점수는 유지한다.
- 예를 들어 5문 모두 기존 답변이 있고 감점 전 종합점수가 80점이면 `80 × 5 ÷ 5 − 5 = 75점`이다.
- 5문 중 3문 완료 상태라면 같은 80점에서 `80 × 3 ÷ 5 − 5 = 43점`이다.

새 질문 미응답 종료에는 4.8을 적용하며 추가 5점 감점은 적용하지 않는다. 표시·반올림은 이후 4.10, 완료 문항 인정 기준은 4.11과 같이 승인받았다. 문항 상태와 실제 구현은 미정이다. 앱 구현이나 실제 채점 시험은 수행하지 않았다.

### 4.10 소수점 표시·반올림 승인 (2026-11-05)

예를 들어 `82.34 → 82.3`, `82.35 → 82.4`, `99.96 → 100.0`으로 표시한다. 중간 계산값은 반올림하지 않고 화면 표시 시에만 반올림한다. 숫자 자료형과 실제 구현은 미정이다. 앱 구현이나 실제 표시 시험은 수행하지 않았다.

### 4.11 완료 문항 인정 기준 승인 (2026-11-05)
사용자가 새 발화에서 STT가 단어를 하나 이상 감지해 답변이 시작되고, 이후 무음 3초로 답변 종료가 판단된 문항을 완료한 것으로 세는 방식을 승인했다. 답변의 품질은 항목별 평가 점수에서 평가한다.

같은 문항을 이어서 말해도 완료 문항 수는 한 개로 유지한다. 중단된 다음 질문을 별도 문항으로 세지 않는 기존 요구사항도 따른다. 완료 수는 진행 상태를 나타내며 중도·무응답 종료의 점수 산출 근거로 사용하지 않는다. 그 종료 처리는 4.30을 따른다.

| 상황 | 완료 문항 집계 |
|---|---|
| 새 질문에 답변할 단어가 하나도 감지되지 않음 | 해당 문항은 미완료이며 7초 무응답 정책 적용 |
| 새 단어 1개 이상 감지 후 무음 3초로 답변 종료 | 해당 문항 1개 완료, 답변 품질은 항목별 점수에서 평가 |
| 완료한 답변을 이어서 말하고 다시 종료 | 같은 문항은 계속 1개로 집계 |

### 4.12 평가 항목별 가중치·제외 시 환산 승인 (2026-11-05)
사용자가 정상 완료 종합점수를 계산할 때 인사·직무 면접에 공통으로 다음 비중을 사용하는 방식을 승인했다. 답변 내용에 합계 80%, 시선·머리 움직임에 합계 20%를 두는 제품 설계 결정이다. 실제 평가 품질을 검증한 가중치는 아니다.

| 평가 항목 | 승인 비중 |
|---|---|
| 답변의 구성 | 25% |
| 답변의 논리력 | 30% |
| 답변의 현실성 | 25% |
| 시선의 움직임 | 10% |
| 머리의 움직임 | 10% |

`정상 완료 종합점수 = 적용 항목의 (항목 점수 × 비중) 합계 ÷ 적용 항목 비중 합계`

비중에는 표의 숫자 25·30·25·10·10을 사용한다. 전면 카메라 오류 또는 TrueDepth 미지원으로 두 움직임 항목이 제외되면 답변 3항목의 비중 합계 80으로 나눠 나머지 비중을 재분배한다. 예를 들어 구성 80점·논리력 90점·현실성 70점·시선 60점·머리 80점이면 5항목 적용 시 `78.5점`, 두 움직임 항목 제외 시 `(80×25 + 90×30 + 70×25) ÷ 80 = 80.625점`이다.

정상 완료 점수는 표시 시에만 반올림한다. 위 제외 예시는 `80.6`으로 표시한다. 답변 3항목의 문항별 점수 통합은 이후 4.13과 같이 승인받았다. 시선·머리 관찰 자료의 점수화, 인사·직무 면접의 평가 관점 반영은 별도 논의가 필요하다. 앱 구현이나 실제 채점·평가 품질 시험은 수행하지 않았다.

### 4.13 답변 문항별 점수 통합 승인 (2026-11-05)
사용자가 답변의 구성·논리력·현실성을 정상 완료한 면접의 완료 문항별로 각각 0~100점 평가하고, 각 항목의 문항별 점수를 단순 평균해 결과 화면의 항목 점수를 구하는 방식을 승인했다. 완료한 모든 문항에 같은 비중을 둔다.

`답변 항목 점수 = 해당 항목의 완료 문항별 점수 합계 ÷ 완료 문항 수`

예를 들어 완료한 3문항의 구성 점수가 50·75·100점이면 구성 항목 점수는 `(50 + 75 + 100) ÷ 3 = 75점`이며 `75.0`으로 표시한다. 이 예시는 이후 승인된 4.14의 문항별 구성 점수 간격에도 맞춘 것이다. 미완료 문항을 0점으로 평균에 넣지 않는다. 중도·자동 무응답 종료는 4.30에 따라 이 평균이나 점수를 산출하지 않는다.

이어서 말한 문항은 기존 답변과 추가 발화를 합친 전체 답변으로 평가해 한 문항 점수만 평균에 포함한다. 문항별 답변 길이에 따른 추가 가중치는 두지 않는다. 완료 문항이 0개인 중도·자동 무응답 종료도 평균·점수를 계산하지 않으며 0점으로 대체하지 않는다.

승인 범위는 답변 3항목의 문항별 평가·통합 방식에 한정한다. 구성 채점 기준은 이후 4.14와 같이 승인받았다. 시선·머리 관찰 자료를 점수로 합치는 방법, 인사·직무 면접의 평가 관점 반영은 별도 논의가 필요하다. 평균에는 반올림 전 점수를 사용하며, 과거 이력의 점수 저장은 추가하지 않는다. 앱 구현이나 실제 채점·평가 품질 시험은 수행하지 않았다.

승인 범위는 구성 항목의 기준·세 단계 배점·환산식이다. 시선·머리 점수화, 실제 AI 평가 방식·프롬프트·출력 형식·오류 처리는 미정이다. 평가 예시별 세부 판정 기준과 실제 평가 품질도 검증이 필요하다. 앱 구현이나 실제 채점·평가 품질 시험은 수행하지 않았다.

### 4.21 시선·머리 이탈 정도별 감점 지정 (2026-11-05)

| 확인한 상태 | 해당 항목의 1회 감점 |
|---|---|
| 중앙 영역 안 | 0점 |
| 중앙 영역을 조금 벗어남 | 0.1점 |
| 중앙 영역을 많이 벗어남 | 0.2점 |
| 화면 끝쪽에 가까움 | 0.3점 |
| 화면 밖으로 벗어남 | 0.4점 |

한 번의 확인에서는 해당 단계의 감점 한 개를 적용하고, 매 확인의 감점량을 누적한다. 시선과 머리의 점수는 각각 계산한다. 각 단계에서 감지한 횟수를 `n1`~`n4`라고 하면 다음과 같이 계산한다.

`항목 점수 = max(0, 100 − (0.1×n1 + 0.2×n2 + 0.3×n3 + 0.4×n4))`

예를 들어 한 항목에서 네 이탈 단계를 각각 10회씩 감지했다면 `100 − (1 + 2 + 3 + 4) = 90.0점`이다. 화면 밖 이탈만 10회 감지했다면 `96.0점`이다. 연속 이탈도 매초 확인마다 해당 단계를 반영하고 기존 하한 0점·표시 시 반올림을 따른다.

사용자가 면접 준비 화면에서 조명이나 다른 이유로 움직임 추적이 어려운 경우 확인 메시지를 표시하고 움직임은 평가하지 않도록 지정했다. 기존 공동 채점 설정에 맞춰 시선·머리 두 항목을 모두 채점 항목과 종합점수에서 제외한다. 설정이 켜져 있거나 기기가 TrueDepth를 지원해도 이 제외 조건을 적용한다.

승인된 요구사항은 준비 화면의 확인 메시지와 두 움직임 항목 제외다. 추적 어려움의 판별 기준·관찰 시간, 최종 일본어 메시지·버튼·확인 후 화면 흐름, 재확인 기능은 미정이다. 면접 도중 새로 추적이 어려워지는 경우는 이후 승인된 4.24를 따른다. 앱 구현이나 조명 조건별 추적·안내·평가 제외 시험은 수행하지 않았다.

### 4.24 면접 도중 추적 어려움 처리 승인 (2026-11-05)

승인 범위는 현재 결과 화면의 평가 제외 상태·이유 표시다. 최종 일본어 문구·배치와 여러 제외 사유가 겹치는 경우의 표시 방식은 미정이다. 기존 제외·종합점수 환산 규칙은 유지하며 과거 이력에 점수·제외 사유를 저장하는 정책은 추가하지 않는다. 앱 구현이나 화면 시험은 수행하지 않았다.

### 4.26 면접 도중 추적 불가 3초 기준 승인 (2026-11-05)

| 상태 | 승인된 처리 |

3초는 경과 시간 기준이며 초당 확인 3회와 같은 뜻으로 바꾸지 않는다. 이후 4.29의 종료 확인 창 표시 시간은 누락 경과 시간에 포함하지 않는다. STT의 답변 종료용 무음 3초와도 별개다. 정상 추적 자료의 구체적인 품질 조건·누락 시작과 회복을 감지하는 방법·시간 측정과 실제 추적 설정은 미정이다. 준비 화면의 품질 기준·관찰 시간은 이번 승인으로 정하지 않는다. 앱 구현이나 실제 추적 누락·시간 경계·채점 시험은 수행하지 않았다.

### 4.27 면접 시작 후 움직임 채점 설정 변경 제한 지정 (2026-11-05)
사용자가 면접 시작 시의 시선·머리 공동 채점 설정을 해당 면접에 적용하는 방식을 승인하고, 면접 시작 후에는 설정을 변경할 수 없으며 변경하려면 모의면접을 먼저 종료해야 한다고 명시했다. 이전의 진행 중 변경값을 다음 면접에 예약하는 제안은 이 변경 금지 규칙으로 대체한다.

설정 잠금의 표시·조작 방식, 면접 중 설정 메뉴 접근 여부, 설정값 저장·최종 일본어 문구·카메라 운용은 미정이다. 사용자 종료의 확인·취소는 이후 4.28과 같이 승인받았다. 이번 문서 변경에서는 설정 잠금이나 사용자 종료의 앱 동작을 구현·시험하지 않았다.

사용자가 진행 중인 모의면접을 직접 종료하려 할 때 확인 창을 표시하고, 종료를 확인한 경우에만 종료하며 취소하면 면접을 유지하는 방식을 승인했다. 설정 변경을 위해 먼저 모의면접을 종료하려는 경우에도 이 사용자 종료 절차를 적용한다. 확인 창을 표시했다는 사실만으로 면접이 종료된 것으로 처리하지 않는다.

### 4.29 종료 확인 창 표시 중 전체 정지 지정 (2026-11-05)
사용자가 확인 창이 떠 있는 동안은 모두 정지하도록 지정했다. 이전에 제안한 확인 창 중 움직임 채점 계속은 대체한다. 종료 확인 창은 면접의 모든 진행·관찰·채점·시간 집계를 정지시키는 구간이다.

| 대상 | 확인 창 표시 중 처리 |
|---|---|

| AI 질문 생성·답변 평가 | 처리 진행과 결과 반영 정지 |
| 질문 음성 재생·답변 음성 인식 | 정지하며 답변에 새 발화를 추가하지 않음 |
| 답변 무음 3초·첫 단어 무응답 7초·타이머 애니메이션 | 경과·카운트다운 정지 |

취소하면 확인 창 표시 전의 면접 단계·답변·점수를 유지하고 타이머를 복원해 재개한다. 단, 응답 타이머의 남은 시간은 이후 4.32의 1초 추가 규칙을 적용한다. 확인 창 중의 시간·관찰·발화를 나중에 소급 반영하거나 누락 감점으로 몰아서 처리하지 않는다. 종료 확인을 선택하면 4.28에 따라 종료한다. 평가·점수 미산출은 4.30, 조기 종료 기록 미저장은 4.31을 따른다. 확인 창 표시 자체는 면접 종료가 아니므로 설정 변경 제한은 유지한다.

이 규칙은 4.17의 전 구간 관찰·채점과 4.26의 추적 누락 경과 시간 집계에서 종료 확인 창 표시 시간을 제외하는 예외다. 일반 AI 대기·답변 무음·평가 대기 등 나머지 구간은 기존 규칙을 따른다. 예를 들어 무응답 7초 중 2초가 지난 뒤 확인 창을 10초 띄웠다가 취소해도 남은 시간은 5초다. 추적 누락 1초 뒤 확인 창을 띄우면 그 표시 시간으로 3초 추적 불가에 도달하지 않는다.

AI·음성·카메라 작업의 실제 정지/취소/보류와 안전한 재개 방법, 재생 위치 처리·동시 사건 순서, 최종 일본어 문구·버튼·배치는 미정이다. 이번 문서 변경에서는 앱 소스·시험을 수정하거나 실제 확인 창·일시정지·재개를 시험하지 않았다.

### 4.30 사용자 중도·자동 무응답 종료의 무평가 지정 (2026-11-05)

조기 종료 시 면접 진행·관찰·시간 집계를 끝낸다. 조기 종료까지 완료한 답변이 있거나 움직임 임시 점수가 있어도 항목별·종합점수를 결과로 확정·표시하지 않는다. 0점을 대신 표시하지 않으며, 평가를 새로 요청하거나 중단 전 평가 결과를 적용해 점수를 보여주지 않는다.

이전 4.8의 완료 비율 감점·완료 0개 시 종합 0점과 4.9의 이어 말하기 실패 추가 5점은 이 종료 방식으로 대체해 적용을 중단한다. 7초 후 재질문·다시 7초 후 종료, STT 새 단어 기준, 답변 종료용 무음 3초, 종료 확인 창의 전체 정지는 유지한다. 사용자 종료에는 확인 절차를 적용하고 자동 무응답 종료는 기존 자동 종료 절차를 따른다.

정상 완료 시의 채점과 조기 종료 시의 무평가를 구분해야 한다. 현재 핵심 소스의 `InterviewSession`은 무응답 후 평가를 요청하고 `OverallScoring`은 이전 감점을 계산하므로 후속 수정·검증이 필요하다. 이번 설계 작업에서는 앱 소스·시험을 수정하지 않았다. 조기 종료 스크립트·기본정보는 이후 4.31에 따라 이력에 저장하지 않으며 조기 종료 후에는 4.33에 따라 모의면접 시작 화면으로 돌아간다.

### 4.31 조기 종료 기록 미저장 지정 (2026-11-05)
사용자가 조기 종료된 면접의 스크립트와 기본정보를 이력에 저장하지 않도록 지정했다. 사용자 확인에 따른 중도 종료와 자동 무응답 종료 모두에 적용하며, 완료한 답변이 있거나 이어서 말하기 후 종료한 경우에도 같다.

조기 종료 면접은 과거 이력에 항목으로 추가하지 않으며 스크립트·면접 시작 일시·회사명·업종·직무·면접 종류를 이력 데이터로 남기지 않는다. 이전의 조기 종료 기록 보관 제안은 채택하지 않는다. 정상 완료 이력의 기존 저장 범위·정렬·삭제 규칙과 조기 종료의 무평가·점수 미산출은 유지한다. 확인 창을 취소해 면접을 계속하다 정상 완료한 경우는 정상 이력 규칙을 따른다.

정상 완료 이력의 구체적인 저장 시점·구조, 진행 중 임시 자료의 해제 방법은 미정이다. 이번 설계 작업에서는 저장 코드나 앱 동작을 구현·시험하지 않았다.

### 4.32 확인 창 취소 후 응답 타이머 잔여 시간 보정 지정 (2026-11-05)
사용자가 확인 창을 닫고 면접을 재개할 때 남은 시간이 1초 미만이면 1초를 추가하도록 지정하고, 첫 단어 대기 7초와 답변 종료용 무음 3초의 두 응답 타이머 모두에 적용하도록 확인했다. 새 질문·재질문 후·이어서 말하기의 해당 응답 대기에 같은 규칙을 적용한다.

`재개 후 남은 시간 = 남은 시간 + 1초 (남은 시간이 1초 미만인 경우)`

1초 이상 남았으면 그대로 유지한다. 최소 1초로 맞추는 것이 아니라 1초를 더하며, 조건 판정에는 화면 표시용 반올림 전의 실제 잔여 시간을 사용한다. 확인 창 표시 시간 자체는 계속 제외하며 보정은 확인 창 취소 후 재개 시점의 실제 잔여 시간으로 판단한다.

| 타이머와 확인 창 표시 전 상태 | 확인 창 10초 후 취소 시 남은 시간 |
|---|---|
| 첫 단어 7초 중 2초 경과 | 5초 |
| 첫 단어 7초 중 6초 경과 | 1초 |
| 첫 단어 7초 중 6.1초 경과 | 0.9초 + 1초 = 1.9초 |
| 답변 무음 3초 중 2.1초 경과 | 0.9초 + 1초 = 1.9초 |

이 보정은 두 응답 타이머에만 적용한다. 추적 누락 3초 집계와 초당 움직임 확인 주기에 1초를 더하지 않는다. 답변·점수·면접 단계의 보존과 확인 창 중 전체 정지는 유지하며 종료 확인을 선택한 경우에는 재개 보정을 적용하지 않는다.

0초 도달과 확인 창 표시가 겹칠 때의 사건 순서, 시간 자료형·표시·실제 예약/재개 방법은 미정이다. 이번 설계 작업에서는 앱 소스·시험을 수정하거나 보정 동작을 실행하지 않았다.

### 4.33 조기 종료 후 시작 화면 복귀 승인 (2026-11-05)
사용자가 사용자 중도 종료와 자동 무응답 종료 후 회사명·업종·직무·면접 종류를 입력하는 모의면접 시작 화면으로 돌아가는 방식을 승인했다. 두 종료 모두 평가·점수 산출·결과 점수 표시·이력 저장 없이 이 화면으로 복귀한다.

사용자가 종료 확인 창을 취소한 경우에는 복귀하지 않고 기존 면접을 재개한다. 정상 완료 면접의 결과 확인·이력 저장 흐름도 유지한다. 시작 화면으로 돌아오는 것은 이전 면접의 답변을 이어 받는 동작이 아니다.

직전 입력값 유지는 이후 4.34와 같이 승인받았다. 종료 사유 안내·최종 일본어 문구·구체적인 화면 전환 방식은 미정이다. 이번 설계 작업에서는 앱 소스·시험을 수정하거나 화면 이동을 구현·시험하지 않았다.

### 4.34 시작 화면 복귀 시 입력값 유지 승인 (2026-11-05)
사용자가 조기 종료 후 시작 화면으로 돌아오면 직전에 입력한 회사명·업종·직무·면접 종류를 입력칸에 유지하는 방식을 승인했다. 사용자 중도 종료와 자동 무응답 종료 모두 같은 흐름이며, 같은 조건으로 다시 연습하거나 필요한 값만 바꿀 수 있다.

이 보존은 시작 화면의 네 입력값에 대한 것이다. 조기 종료의 스크립트·기본정보를 이력에 저장하지 않는 4.31의 규칙과 평가·점수 미산출은 유지한다. 이전 면접의 답변을 이어 받는 흐름으로 바꾸지 않으며 새 면접은 새로 시작한다. 종료 확인 창을 취소한 경우에는 기존 면접 재개 규칙을 따른다.

앱을 완전히 종료한 뒤 재실행할 때까지 보존할지, 구체적인 상태 구조·영구 저장·초기화 조작·종료 사유 안내는 미정이다. 이번 설계 작업에서는 앱 소스·시험을 수정하거나 입력값 유지 동작을 구현·시험하지 않았다.

### 4.35 앱 재실행 후 마지막 입력값 복원 검토 (제안, 미승인)
마지막 회사명·업종·직무·면접 종류를 기기 내부에 별도 보관해, 앱을 완전히 종료한 뒤 다시 열어도 시작 화면에 채워 두는 안을 제안한다. 재실행할 때 같은 조건을 다시 입력하는 수고를 줄이려는 제안이다.

이 영구 보관은 아직 승인받지 않았다. 조기 종료 면접의 이력은 계속 만들지 않는다. 저장 기술·시점·초기화·백업 정책과 입력값 복원 안내는 별도 논의가 필요하다. 이번 설계 작업에서는 저장·복원 기능을 구현·시험하지 않았다.

## 5. 과거 기록
- 정상 완료한 면접의 질문·답변 스크립트와 면접 시작 일시·회사명·업종·직무·면접 종류(인사/직무)를 휴대폰 내부에 저장한다. 4.31에 따라 조기 종료 면접은 저장하지 않는다.
- 스크립트에는 각 문항의 최종 질문과 기존 답변·추가 발화를 합친 전체 답변을 보관하며, 이어서 말하기로 중단된 질문은 제외한다. 자세한 승인 범위는 [DATA.md](../system-design/DATA.md)의 1.5를 따른다.
- 사용자는 과거 모의면접의 스크립트를 다시 확인할 수 있다.
- 기본정보는 기록 구분과 당시 연습 조건 확인을 위해 보관한다. 과거 기록은 면접 시작 일시를 기준으로 최신 기록을 위에 표시한다. 목록 구성과 날짜·시간의 표시 형식은 미정이다.
- 사용자가 기록을 한 건씩 선택해 삭제할 수 있다. 삭제 전 확인 창을 표시하고, 삭제를 확인하면 해당 기록의 스크립트와 기본정보를 함께 삭제하며 취소하면 유지한다. 승인 범위는 [DATA.md](../system-design/DATA.md)의 1.4를 따른다. 삭제 버튼 위치·조작 방식·최종 일본어 문구는 미정이다.

### 5.1 과거 기록 표시 순서 승인 (2026-11-05)
사용자가 면접 시작 일시를 기준으로 최신 기록을 위에 표시하는 방식을 승인했다. 최근 연습을 쉽게 다시 확인하기 위한 순서다. 같은 시작 일시를 가진 기록의 순서, 목록 구성과 날짜·시간 표시 형식은 미정이다. 화면 구현이나 실제 정렬 시험은 수행하지 않았다.

## 6. 공통 레이아웃·네비게이션
- 레이아웃, 화면별 최종 명칭, 전역 탐색 구조는 미정이다.
- 서비스 화면 문구는 일본어로 작성한다.
- 취업활동 관리 기능의 화면과 흐름은 아직 논의하지 않았다.

## 임시 소스 구현과 화면의 경계

종료 확인 창의 실제 표시·취소 시각을 전달받아 시간을 보존하는 Core 처리를 추가했다. 표시 중 자료 적용은 멈추고 취소 시 이전 단계·답변·점수를 유지한다. 화면·일본어 문구·장치 작업의 실제 중단·재개·재생 위치·확인 후 이동은 구현하지 않았다. 무평가 코드 변경도 추가 승인을 받았다. 무응답 종료와 현재 창 번호가 일치하는 사용자 종료 확정을 반영했다.

`ios_temp/`에 질문 설정·점수 계산·점수 표시 문자열을 검증하는 핵심 소스·시험을 작성했다. 움직임 구간·제외 계산과 7초/3초·이어서 말하기·평가 재개 진행도 합성 입력으로 검증했다. `resultsReady`는 결과 표시 전 내부 상태이며 `resultsWillDisplay`에서 움직임 최종 점수를 반영한다. 실제 화면 분리나 표시 대기 흐름을 확정한 것은 아니다. 실제 점수 화면은 구현하지 않았다. 무평가 종료에는 항목별·종합점수가 없다. 설정 화면·화면 배치·일본어 문구·탐색 구조는 구현하지 않았으며 기존 미정 상태를 유지한다. 사용자 Xcode 프로젝트 생성 후 앱 대상에 소스를 옮기는 방법은 [이전 안내](../../ios_temp/INTEGRATION.md)를 따른다.

카운트다운 중·결과 표시 뒤의 답변 재개와 관찰 자료가 전혀 없는 경우에는 임시 소스가 승인 필요 경계를 반환한다. 무평가 종료 뒤의 진행·평가·관찰 사건은 무시한다. 추가 승인에 따라 무응답 종료는 점수 없이 끝나며 이력 대상에서도 제외한다. 현재 창 번호가 일치하는 사용자 확인 종료도 같은 종료로 연결했으며 실제 화면 이동은 구현하지 않았다. 실제 질문/재질문 문구·음성/AI 취소·타이머 예약·동시 사건 우선순위는 연결하지 않았다.

종료 확인 정지/취소 재개의 Core 연결 시험은 질문 준비부터 결과 표시 대기까지 9단계를 포함한다. 이는 화면·음성·카메라·모델이 실제로 정지하는 UI 자동화나 실기기 검증을 수행한 결과가 아니다.
