## 1. 개요

### 1.1 저장 범위
- 과거 모의면접의 영구 저장 대상은 질문·답변 스크립트와 면접 시작 일시·회사명·업종·직무·면접 종류(인사/직무)다. 기본정보의 동반 저장은 2026-11-05 사용자 승인을 받았다.
- 스크립트에는 각 문항의 최종 질문과 기존 답변·추가 발화를 합친 전체 답변을 보관한다. 이어서 말하기로 중단된 질문은 저장할 스크립트에서 제외한다.
- 면접 중 시선·머리 움직임을 관찰하고, 종료 시 점수와 스크립트를 표시한다. 음성·영상·움직임 관찰 원본·평가점수를 과거 면접 이력으로 저장하는 기능은 요구사항에 포함하지 않는다.
- 회사명·업종·직무·면접 종류와 면접 시작 일시는 이력의 기본정보로 함께 보관한다. 질문 개수는 면접에 사용하며, 개수의 별도 영구 저장 여부는 미정이다. 내부 식별자·문항 순서 등을 표현할 구체적인 데이터 구조는 아직 정하지 않았다.
- STT는 SpeechAnalyzer + SpeechTranscriber를 사용하는 기기 내부 처리 방식으로 승인받았다. 필요한 언어 모델의 다운로드·설치 상태와 일본어 지원은 실제 기기에서 확인해야 한다.
- 제품 최종 AI 처리 방식과 외부 전송 허용 여부는 미정이다. 외부 STT 서비스로 음성을 전송하는 구성은 승인받지 않았다. 스크립트와 승인된 기본정보는 휴대폰 내부에 보관한다.

### 1.2 로컬 저장 도구 선정 승인 (2026-11-05)
사용자가 SwiftData를 기기 내부 저장 도구로 승인했고, CloudKit 자동 동기화를 끄는 구성도 승인했다. 아래는 선정 시 비교한 내용이다.

| 후보 | 방식 | 현재 요구사항에 대한 검토 |
|---|---|---|
| [SwiftData](https://developer.apple.com/documentation/swiftdata/) | Apple의 기기 내부 데이터 저장·조회 도구 | SwiftUI와 연동해 과거 스크립트를 목록·상세 화면에 표시하기에 적합하다고 판단 |
| JSON 파일 + Codable | [JSONEncoder](https://developer.apple.com/documentation/foundation/jsonencoder) 등으로 스크립트를 JSON 데이터로 변환해 파일에 저장 | 단순한 스크립트 보관 대안. 파일 읽기·쓰기와 목록 관리·화면 갱신을 직접 구성해야 함 |

- SwiftData는 [앱 재실행 후에도 모델을 보관하고 SwiftUI에서 조회하는 기능](https://developer.apple.com/documentation/swiftdata/preserving-your-apps-model-data-across-launches)을 제공한다. 이 저장 기능을 위해 자체 서버를 운영할 필요는 없다.
- 승인된 구성은 기기 내부 저장이며, `ModelConfiguration(cloudKitDatabase: .none)`으로 SwiftData의 CloudKit 자동 동기화를 비활성화한다. [Apple의 설정 문서](https://developer.apple.com/documentation/swiftdata/modelconfiguration/cloudkitdatabase-swift.struct/none)는 해당 옵션이 관리형 CloudKit 동기화를 끈다고 설명한다.
- 기록 구분을 위한 기본정보는 1.3, 기록별 삭제는 1.4와 같이 승인받았다. 데이터 구조와 나머지 보관·백업 정책은 미정이다. CloudKit 자동 동기화 비활성화만으로 기기 백업 정책까지 결정한 것으로 간주하지 않는다. 저장 기능 구현이나 데이터 파일 생성은 수행하지 않았다.

### 1.3 과거 면접 기본정보 저장 승인 (2026-11-05)
사용자가 과거 기록을 구분하고 면접 조건을 다시 확인할 수 있도록 다음 기본정보를 질문·답변 스크립트와 함께 휴대폰 내부에 저장하는 구성을 승인했다.

| 승인된 정보 | 보관 목적 |
|---|---|
| 면접 시작 일시 | 같은 조건으로 여러 번 진행한 면접을 구분 |
| 회사명 | 어느 회사를 대상으로 연습했는지 확인 |
| 업종·직무 | 질문·답변을 당시 연습 조건과 함께 확인 |
| 면접 종류(인사/직무) | 어떤 종류의 면접을 연습했는지 확인 |

이 승인은 보관할 정보의 범위에 대한 것이며, 엔티티·필드 타입·관계 등 구체적인 데이터 구조는 미정이다. 점수·음성·영상·움직임 원본 저장을 포함하지 않는다. 질문 개수는 3~7문이라는 기존 요구사항을 유지하며, 개수의 별도 저장 여부도 아직 정하지 않았다.

### 1.4 과거 기록 삭제 방식 승인 (2026-11-05)
- 사용자가 과거 기록을 한 건씩 선택해 삭제하는 방식을 승인했다.
- 삭제 전 확인 창을 표시하고, 사용자가 삭제를 확인하면 해당 기록의 스크립트와 기본정보를 앱의 저장소에서 함께 삭제한다. 취소하면 기록을 유지한다.
- 승인 범위는 기록별 삭제와 확인 절차다. 일괄 삭제·자동 삭제·보관 기간·복구 기능·백업 정책은 미정이다. 삭제 기능 구현이나 실제 데이터 삭제는 수행하지 않았다.

### 1.5 최종 질문·전체 답변 스크립트 보관 승인 (2026-11-05)
사용자가 이어서 말하기로 중단된 질문은 과거 스크립트에서 제외하고, 각 문항의 최종 질문과 그에 대한 전체 답변을 보관하는 방식을 승인했다. 이어서 말한 내용은 해당 문항의 기존 답변과 합쳐 보관한다. 승인된 기본정보 저장 범위는 유지하며, 구체적인 데이터 구조와 저장 시점은 미정이다. 저장 기능 구현이나 실제 저장 시험은 수행하지 않았다.

## 5. 관계와 제약 조건
<!-- ERD로 표현되지 않는 규칙. 예: 삭제 시 연쇄 정책, 유일성 조건, 상태 전이 제한. -->
- 질문 개수는 3~7문이며, 앱 첫 사용 시 기본값은 5문이다. 사용자가 설정 등의 메뉴에서 변경할 수 있다. 설정값의 저장 방식은 미정이다.
- 이어서 말하기로 중단된 다음 질문은 문항 수에 포함하지 않는다. 전체 답변을 바탕으로 다시 검토한 질문을 같은 문항 번호로 제시한다.
- 각 질문과 사용자 답변은 결과 화면과 과거 스크립트에서 함께 확인할 수 있어야 한다.
- 기록 삭제를 확인하면 해당 기록의 스크립트와 기본정보를 함께 삭제한다. 삭제 확인 창에서 취소하면 기록을 유지한다.
- 전면 카메라가 정상 동작하지 않거나 TrueDepth를 지원하지 않으면 시선·머리 움직임 점수를 채점 및 종합점수에서 제외한다. 0점으로 저장하거나 계산에 포함하지 않는다.
- 준비 화면에서 조명 등으로 움직임 추적이 어려우면 확인 메시지를 표시하고 시선·머리 두 항목을 모두 평가·종합점수에서 제외한다. 공동 설정이 켜져 있거나 기기가 지원되어도 적용한다. 0점·초기값 100점·화면 밖 감점으로 대체하지 않는다. 추적 어려움의 판별 기준·관찰 시간·메시지·확인 동작·재확인 기능은 미정이다.
- 면접 도중 추적 불가로 판단되면 안내 후 그 면접의 시선·머리 평가 전체를 제외하고 면접을 계속한다. 앞서 누적된 움직임 감점도 종합점수에서 제외하고 답변 3항목을 기존 비중 합계 80으로 환산한다. 무응답 감점·표시 시 반올림은 기존 규칙을 따른다. 도중 연속 3초와 그 미만 누락의 처리는 다음 항목을 따른다. 정상 자료 판별 기준·안내 문구와 표시 방식·제외 후 추적 운용은 미정이다.
- 면접 도중 시선·머리 중 하나라도 정상 추적 자료를 3초 연속 얻지 못하면 두 항목 전체를 제외한다. 3초 미만 누락은 관찰하지 못한 항목의 해당 확인만 감점하지 않고 추적 회복 후 채점을 계속한다. 정상 관찰 가능한 항목은 기존 규칙을 따른다. 회복으로 끊긴 별개의 누락 구간은 합치지 않는다. 경과 시간 기준이며 확인 3회·STT 무음 3초와 구분한다. 정상 자료의 품질 조건·누락/회복 감지·시간 측정 구현은 미정이다.
- 결과 화면에서 제외된 시선·머리 항목에는 숫자 점수 대신 평가 제외 상태와 이유를 표시한다. 이유는 공동 설정·기기/카메라 조건·준비 화면 추적 어려움·면접 도중 추적 불가의 기존 제외 조건과 연결한다. 최종 일본어 문구·배치와 중복 사유 표시는 미정이며 과거 이력의 점수·제외 사유 저장은 추가하지 않는다.
- 시선·머리 채점 범위는 면접 시작부터 결과 표시 직전까지 전 구간이다. 질문 준비·재생, 첫 단어·무응답 대기, 재질문, 답변·무음, 이어서 말하기 전후와 평가 대기도 포함한다. 면접 시작 전 준비 화면과 결과 표시 이후는 범위 밖이다. STT 단어 감지·무음 3초의 답변 상태로 움직임 자료 반영을 제한하지 않는다. 중단된 질문의 문항 수·스크립트 제외와 움직임 채점 범위는 구분한다. 자료의 구체적인 구조·추적 실패 판별 기준은 미정이며 준비 화면과 면접 도중 추적 어려움의 처리는 앞선 승인된 제외 규칙을 따른다.
- 시선과 머리는 각각 초당 한 번 중앙에 위치하는지 확인한다. 평가 가능한 두 항목은 면접에서 각각 100점으로 시작하며, 매 확인마다 해당 항목의 이탈 정도에 따라 조금 벗어남 0.1점·많이 벗어남 0.2점·화면 끝쪽에 가까움 0.3점·화면 밖 이탈 0.4점 중 하나를 감점한다. `항목 점수 = max(0, 100 − 해당 항목의 매 확인별 감점량 합계)`이며 연속 이탈도 매초 누적한다. 중앙 사각 영역의 가로·세로 비율 50%·70%·90%, 경계선의 안쪽 포함과 화면 경계선의 화면 안 분류는 승인받았다. 실제 기준점·화면 좌표 판정·보정·카메라 및 추적 설정·추적 실패 판별 기준·안내 표시 방식은 미정이다. 기존 0~100점 범위와 카메라 오류·TrueDepth 미지원·준비 화면과 면접 도중 추적 어려움의 두 항목 제외 규칙을 따른다.
- 설정 하나로 시선·머리 채점을 함께 켜고 끈다. 평가 가능한 기기에서 첫 사용 기본값은 켜짐이다. 두 항목의 점수는 각각 유지한다. 꺼진 두 항목은 평가·종합점수 계산에서 제외하고 답변 3항목의 비중 합계 80으로 환산하는 기존 계산식을 적용하며 0점으로 취급하지 않는다. 켜져 있어도 기기 조건·준비 화면과 면접 도중 추적 어려움에 따른 제외가 우선한다. 면접 시작 후 공동 설정값은 변경할 수 없으며 변경하려면 모의면접을 먼저 종료해야 한다. 종료 후 변경값은 새 면접에 적용한다. 설정 잠금 표시·메뉴 접근·사용자 종료의 세부 흐름·설정 저장·비활성 시 카메라 운용은 미정이다.
- 답변이 시작된 뒤의 무음 기준은 3초다. 종료까지 남은 시간을 타이머 애니메이션으로 표시한다. 3초 후 LLM의 다음 질문 준비 중이나 질문 음성 재생 중에도 이어서 말하기 버튼을 사용할 수 있다. 선택하면 질문 준비·재생을 중단하고 직전 답변을 이어서 받은 뒤, 기존 답변과 추가 발화를 포함한 전체 답변을 바탕으로 다음 질문을 다시 검토한다.
- 중단된 질문은 저장할 스크립트에서 제외하고 각 문항의 최종 질문·전체 답변을 보관한다. 자세한 승인 범위는 1.5를 따른다. 취소·재개·문항 번호를 표현할 구체적인 데이터 구조는 미정이다.
- 발화 시작은 STT가 새 발화에서 단어를 하나 이상 감지한 시점이다. 재개 전 저장된 기존 답변의 단어만으로는 재개한 발화의 시작으로 판단하지 않는다. 종전의 첫 단어 무제한 대기는 무응답 7초 규칙으로 변경했으며, 이어서 말하기 후에도 같은 규칙을 적용한다.
- STT가 새 발화의 단어를 하나 이상 감지해 답변이 시작되고 이후 무음 3초로 답변이 종료된 문항을 완료로 센다. 같은 문항을 이어서 말해도 완료 문항 수는 한 개로 유지한다. 답변 품질은 항목별 점수에서 평가한다. 문항 상태를 표현할 구체적인 자료형과 구현은 미정이다.
- 마지막 답변 이후 평가 중에도 이어서 말하기를 제공한다. 선택하면 평가를 중단하고 마지막 답변에 추가 발화를 받은 뒤, 전체 답변으로 다시 평가한다. 재개한 발화에도 기존 STT 시작·무음 3초 기준을 적용한다. 점수의 과거 이력 저장은 추가하지 않는다.
- 적용되는 각 평가 항목과 종합점수의 범위는 0~100점이며 소수점 첫째 자리까지 표시한다. 둘째 자리 숫자가 5 이상이면 올리는 반올림은 화면 표시 시에만 적용하고, 중간 계산값은 반올림하지 않는다. 정수도 `80.0`처럼 표시한다. 숫자 자료형·시선과 머리의 실제 화면 좌표 판정과 보정은 미정이다.
- 면접 종료 후 완료 문항마다 구성·논리력·현실성을 각각 0~100점으로 평가하고, 항목마다 완료 문항 점수의 단순 평균을 구한다. 모든 완료 문항의 비중은 같으며, 이어서 말한 문항은 기존·추가 발화를 합친 전체 답변을 한 번 포함한다. 미완료 문항은 평균에서 제외하고 미진행분은 종합점수의 완료 비율 감점으로 반영한다. 완료 0개면 평균을 계산하지 않고 최종 종합점수 0점을 적용하며 이때 항목별 표시는 미정이다.
- 문항별 구성 점수는 핵심 제시·정보 순서·내용 집중·마무리를 같은 비중으로 평가한다. 각 기준을 미충족 0점·부분 충족 1점·충족 2점의 정수로 매기고 `세부 기준 점수 합계 ÷ 8 × 100`으로 환산한다. 답변 길이와 형식은 자유롭게 두며, 기존·추가 발화를 합친 전체 답변을 대상으로 한다. 실제 AI 평가와 세부 판정 기준의 검증은 미정이다.
- 문항별 논리력 점수는 근거 제시·근거와 결론의 연결·같은 답변 안의 일관성·비약 억제를 같은 비중으로 평가한다. 각 기준을 미충족 0점·부분 충족 1점·충족 2점의 정수로 매기고 `세부 기준 점수 합계 ÷ 8 × 100`으로 환산한다. 기존·추가 발화를 합친 전체 답변을 한 번 평가하고 완료 문항 평균을 적용한다. 다른 문항 간 진술 비교·사실 확인·실제 AI 평가 방식은 미정이다.
- 문항별 현실성 점수는 구체성·실행 가능성·직무와 상황 적합성·결과의 개연성을 같은 비중으로 평가한다. 각 기준을 미충족 0점·부분 충족 1점·충족 2점의 정수로 매기고 `세부 기준 점수 합계 ÷ 8 × 100`으로 환산한다. 기존·추가 발화를 합친 전체 답변을 한 번 평가하고 완료 문항 평균을 적용한다. 질문 유형별 세부 판정·직무와 회사의 사실 확인·경험의 진위 확인·기준 자료 확보·실제 AI 평가 방식은 미정이다.
- 인사·직무 면접 공통으로 구성 25·논리력 30·현실성 25·시선 10·머리 10의 비중을 적용한다. `감점 전 종합점수 = 적용 항목의 (항목 점수 × 비중) 합계 ÷ 적용 항목 비중 합계`로 계산한다. 공동 설정·전면 카메라 오류·TrueDepth 미지원·준비 화면과 면접 도중 추적 어려움으로 두 움직임 항목을 제외하면 남은 답변 3항목의 가중합을 비중 합계 80으로 나눈다. 이 감점 전 종합점수에 승인된 무응답 종료 감점을 적용한다.
- STT 시작 후 7초 동안 단어가 하나도 감지되지 않으면 재질문한다. 재질문 이후 STT 시작 후에도 7초 동안 단어가 하나도 감지되지 않으면 면접을 종료하고 승인된 감점 규칙을 적용한다. 새 질문 미응답과 이어서 말하기 실패의 계산은 다음 항목들을 따른다. 조기 종료 이력의 저장 여부는 미정이다.
- 새 질문 미응답 종료 시 `최종 종합점수 = 완료 문항 기준 감점 전 종합점수 × 완료 문항 수 ÷ 설정 문항 수`를 적용한다. 항목별 점수는 품질 평가 점수로 유지하며 미진행분 감점은 종합점수에 반영한다. 완료 문항이 0개면 최종 종합점수는 0점이다. 시선·머리의 구간 비율·감점량은 승인받았으며 실제 기준점·화면 좌표 판정과 보정은 미정이다.
- 이어서 말하기 무응답 종료 시 기존 답변과 해당 문항의 완료 인정을 유지한다. `최종 종합점수 = max(0, 완료 문항 기준 감점 전 종합점수 × 완료 문항 수 ÷ 설정 문항 수 − 5)`를 적용하며 추가 5점은 종료 시 한 번 감점한다. 항목별 품질 점수는 유지한다.
- 위 무응답 처리는 이어서 말하기 선택 후의 새 발화 대기에도 동일하게 적용한다. 승인된 기본 감점은 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.8, 이어서 말하기 실패의 추가 감점은 4.9, 소수점 표시·반올림은 4.10, 완료 문항 인정 기준은 4.11, 공통 가중치·제외 시 환산은 4.12, 답변 3항목의 문항별 점수 단순 평균은 4.13, 구성 채점 기준은 4.14, 논리력 채점 기준은 4.15, 현실성 채점 기준은 4.16을 따른다. 시선·머리 채점 범위는 사용자가 지정한 4.17, 매초 중앙 확인·누적 감점은 4.18, 공동 채점 설정은 4.19, 첫 사용 기본값 켜짐은 4.20, 이탈 정도별 감점량은 4.21, 승인된 중앙 50%·70%·90%의 구간 경계는 4.22, 준비 화면의 추적 어려움 안내·두 항목 제외는 4.23을 따른다. 면접 도중 추적 불가의 안내·두 항목 전체 제외·면접 계속은 승인된 4.24를 따른다. 결과 화면에서 제외된 시선·머리 항목에 숫자 대신 평가 제외 상태와 이유를 표시하는 방식은 4.25, 도중 추적 불가의 연속 3초·그 미만 누락 처리는 4.26과 같이 승인받았다. 면접 시작 후 공동 설정 변경 금지·변경 전 모의면접 종료는 4.27과 같이 지정받았다. 사용자 종료 전 확인 절차는 4.28의 미승인 제안이다. 과거 이력의 점수·원본 관찰 자료 저장은 추가하지 않는다.
- STT 단어 판별·중간/확정 결과 처리 방식과 무음 검출 방법은 미정이다. STT 단어 감지는 발화 시작 조건이며, 이를 무음 판정 방법까지 확정한 것으로 간주하지 않는다. 상세 무응답 정책은 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.7을 따른다.

## 임시 점수 계산 자료

점수·세부 배점·문항 번호는 `ios_temp/Sources/Core/`의 메모리 값으로만 다룬다. 분자·분모 정수로 점수를 유지하며 반올림은 표시 문자열 생성 때만 한다. 세부 점수는 시험에서 제공하고 AI 평가는 연결하지 않는다. 평균 자료가 없는 상태와 0점은 구분한다. SwiftData 엔티티·이력 저장 필드와 시점은 정하지 않았으며 점수의 영구 저장도 추가하지 않았다.

움직임 시험은 `MovementScoringTests.swift`에 화면 위치·누락/회복 시각을 직접 전달한다. 확인에서 자료가 없으면 해당 항목의 감점을 건너뛰며, 연속 누락 시간은 별도의 정상 자료 유무 사건으로 전달한다. 3초 도달 시 두 항목과 이전 감점을 전체 제외한다. 정상 자료의 품질·누락 시각 감지와 실제 초당 예약은 정하지 않는다. 복수 제외 사유는 순서 없는 집합으로 보관해 화면 표시 우선순위를 만들지 않으며 저장 이력에 추가하지 않는다.
