# OPERATIONS

> 최소 iOS 버전은 26.0이다. Xcode 프로젝트 생성은 사용자 담당이다. 임시 Swift 소스는 `ios_temp/`에 작성하고 아래 명령으로 독립 검증한다. 실제 앱의 빌드·실행 명령은 프로젝트 생성 후 정한다.

### 1.1 사용자가 보유한 테스트 기기 (2026-11-05)
| 기기 | 칩 | TrueDepth 카메라 | Apple Intelligence | 실제 설치된 iOS |
|---|---|---|---|---|
| [iPhone 14 Plus](https://support.apple.com/en-sg/111854) | A15 Bionic | 탑재 | 미지원 | 미확인 |
| [iPhone XR](https://support.apple.com/en-la/111868) | A12 Bionic | 탑재 | 미지원 | 미확인 |

- 두 기기를 보유하고 있다는 사용자 확인을 기록했다. 출시 지원 목표는 가능하다면 iPhone 13 이상이고, 최소 OS는 iOS 26.0이다. 하드웨어 지원 가능 여부는 검증이 필요하며, 보유 기기 목록을 출시 지원 범위로 간주하지 않는다.
- 칩·카메라 탑재 여부는 Apple 공식 사양, Apple Intelligence 지원 여부는 [공식 지원 조건](https://support.apple.com/en-gb/121115)으로 확인했다. 실제 카메라 동작·권한 상태·추적 품질은 아직 시험하지 않았다.
- XR은 [iOS 26 호환 기기 목록](https://support.apple.com/en-ie/guide/iphone/-iphe3fa5df43/ios)에 포함되지 않아 승인된 OS 하한으로 구성할 앱의 설치 대상이 아니다. 보유 기기 정보는 유지한다.
- 모델 다운로드·설치 및 실제 기기에서의 LLM·음성·시선/머리 움직임 시험은 아직 수행하지 않았다.

### 1.2 출시 지원 목표와 검증 범위 (2026-11-05)
- 사용자 희망: 가능하다면 iPhone 13 이상을 정식 출시 때 지원한다. 성능 검증 없이 지원을 확정하지 않는다.
- 현재 iPhone 13 실기기는 보유 테스트 기기에 포함되지 않는다. 14 Plus 또는 XR의 측정 결과만으로 iPhone 13에서의 동작·성능을 검증했다고 보고하지 않는다.
- [iPhone 13](https://support.apple.com/en-ie/111872)은 A15 Bionic·4코어 GPU, [14 Plus](https://support.apple.com/en-sg/111854)는 A15 Bionic·5코어 GPU다. 같은 칩 이름만으로 동일한 실행 성능을 가정하지 않는다.
- iPhone 13 이상이라는 조건부 하드웨어 지원 목표와 별도로, 앱이 요구할 최소 iOS 버전은 26.0으로 승인받았다. 시험 순서·합격 기준은 미정이다. 첫 검증 모델은 LFM2.5-1.2B-JP-202606, 검증용 실행 도구는 MLX Swift LM으로 사용자 승인을 받았으며, 제품 최종 모델은 미정이다.

### 1.3 첫 검증 모델 선정 승인 (2026-11-05)
- 첫 검증 모델: `LFM2.5-1.2B-JP-202606`.
- 확인할 항목: 일본어 면접 평가 품질, 응답 시간, 메모리 사용량, 발열. 합격 기준과 검증용 질문·답변 자료는 아직 정하지 않았다.
- 검증용 실행 도구는 이후 MLX Swift LM, 최소 iOS 버전은 26.0으로 승인받았다. 모델 파일의 압축 형식, 실행 도구의 버전·연동 설정과 검증 앱 구성은 미정이다.
- Mac에서 Xcode 개발 도구 경로와 Swift 실행 파일의 존재를 읽기 전용으로 확인했다. 현재 확인한 버전은 1.4를 따른다. 빌드, 모델 다운로드·설치, 실제 기기 시험은 수행하지 않았다.
- 자세한 승인 범위와 실행 도구 선정 기록은 [ARCHITECTURE.md](ARCHITECTURE.md)를 따른다.

### 1.4 검증용 실행 도구 선정 승인 (2026-11-05)
- 사용자가 MLX Swift LM을 검증용 모델 실행 도구로 승인했다. 패키지 설치·버전 고정·연동 설정·앱 구현은 아직 수행하지 않았다.
- 로컬 개발 도구를 읽기 전용으로 확인한 결과 Xcode 27.2, Build version 27B52다. 보유 iPhone에 실제 설치된 iOS 버전은 미확인이다.
- 최소 iOS 버전은 이후 26.0으로 승인받았다. 비교 근거와 후속 음성 인식 제안은 [ARCHITECTURE.md](ARCHITECTURE.md)의 6.9·6.10을 따른다.

### 1.5 최소 iOS 버전 승인 (2026-11-05)
- 사용자가 최소 iOS 버전을 26 이상으로 승인했다. 향후 프로젝트의 설치 하한은 iOS 26.0으로 구성한다.
- iPhone 14 Plus에 설치된 OS가 26 이상인지 확인해야 한다. XR은 이 하한을 충족할 수 없다.
- 문서에 요구사항을 반영했으며, 아직 생성되지 않은 앱의 빌드 설정을 변경한 것은 아니다.
- 음성 인식 도구는 이후 SpeechAnalyzer + SpeechTranscriber로 승인받았다. 지원되지 않을 때의 처리와 언어 모델 다운로드 시점·안내 방식은 미정이다.

### 1.6 음성 인식 도구 승인 (2026-11-05)
- 사용자가 기기 내부 STT 도구로 SpeechAnalyzer + SpeechTranscriber를 승인했다.
- 기기 지원 여부와 일본어 지원·설치 상태, 인식 품질·지연 시간을 실기기에서 검증해야 한다. 실제 검증은 아직 수행하지 않았다.
- 필요한 경우 언어 모델 다운로드·설치를 진행할 시점과 안내 방식, 지원되지 않거나 인식에 실패했을 때의 처리는 미정이다. 답변 중 무음 기준과 관련 화면 요구사항은 이후 1.14와 같이 지정받았다.
- 음성 인식 기능 구현·언어 모델 설치·외부 음성 인식 서비스 도입은 수행하지 않았다. TTS 도구는 이후 AVSpeechSynthesizer로 승인받았다.

### 1.7 질문 음성 출력 도구 승인 (2026-11-05)
- 사용자가 TTS 도구로 AVSpeechSynthesizer를 승인했다.
- 사용할 일본어 목소리·품질·읽기 속도·음높이, 필요한 음성의 다운로드 안내 방식은 미정이다.
- 실기기에서 음성의 설치 상태, 회사명·직무 용어의 발음, 재생 완료 후 답변 차례 전환과 오프라인 재생을 확인해야 한다. 실제 검증은 아직 수행하지 않았다.
- 음성 출력 기능 구현·음성 설치·재생 시험은 수행하지 않았다. 시선·머리 움직임 관찰 기술은 이후 ARKit으로 승인받았다.

### 1.8 시선·머리 움직임 관찰 기술 승인 (2026-11-05)
- 사용자가 시선·머리 움직임 관찰 기술로 ARKit을 승인했다.
- TrueDepth 지원·전면 카메라 정상 동작을 확인하며, 조건을 충족하지 않으면 두 움직임 항목을 모두 채점 및 종합점수에서 제외한다.
- 준비 화면에서 조명 등으로 추적이 어려우면 확인 메시지를 표시하고 두 움직임 항목을 모두 제외한다. 상세 요구사항과 미정 사항은 1.38을 따른다.
- 기기 지원 여부, 시선 추정 정확도, 준비 화면의 적정 거리, 보정 방법, 추적 실패 판별 기준은 확인·논의가 필요하다. 도중 추적 불가 시 처리는 이후 1.39와 같이 승인받았다. 초당 중앙 확인·100점 시작·누적 감점 방식은 이후 1.33과 같이 사용자가 지정했으며 구간 비율·감점량은 이후 1.36·1.37과 같이 승인받았다. 실제 기준점·좌표 변환과 보정·추적 품질 기준은 미정이다.
- ARKit 연동·카메라 시험·거리 보정·실제 기기 추적 시험은 수행하지 않았다. 앱 개발 언어·화면 도구는 이후 Swift·SwiftUI로 승인받았다.

### 1.9 앱 개발 언어·화면 도구 승인 (2026-11-05)
- 사용자가 개발 언어 Swift와 화면 도구 SwiftUI를 승인했다. 언어 버전, 프로젝트 구조, 앱 생성·구현 범위는 아직 정하지 않았다.
- 테스트 구성은 이후 1.10과 같이 승인받았다. 앱 프로젝트나 화면 코드는 아직 생성하지 않았다.

### 1.10 테스트 구성 승인 (2026-11-05)
- 사용자가 단위·통합 테스트에 Swift Testing, UI 자동화에 XCTest + XCUIAutomation, 성능 측정에 XCTest를 사용하는 구성을 승인했다. 역할과 예시는 [ARCHITECTURE.md](ARCHITECTURE.md)의 6.14를 따른다.
- 일본어 음성·시선 추정·LLM 평가 품질과 전체 면접 중 발열은 실기기에서 별도로 확인해야 한다.
- 구체적인 테스트 대상·구조·실행 명령·성능 합격 기준은 미정이다. 테스트 파일 생성·시험 실행·앱 구현은 수행하지 않았다.

### 1.11 로컬 저장 구성 승인 (2026-11-05)
- 사용자가 SwiftData를 기기 내부 저장 도구로 승인했고 CloudKit 자동 동기화 비활성화도 승인했다. 향후 저장 기능 구현에 `ModelConfiguration(cloudKitDatabase: .none)`을 사용한다.
- 기본정보 저장은 이후 1.12, 기록별 삭제는 1.13과 같이 승인받았다. 스크립트·기본정보의 구체적인 데이터 구조와 나머지 보관·백업 정책은 미정이다. 자동 동기화 비활성화를 기기 백업 정책의 확정으로 간주하지 않는다.
- 앱 프로젝트·데이터 모델·저장 파일을 생성하거나 저장 기능을 시험하지 않았다. 구체적인 데이터 정책과 구현 범위는 승인 후 적용한다.

### 1.12 과거 면접 기본정보 저장 승인 (2026-11-05)
- 사용자가 면접 시작 일시·회사명·업종·직무·면접 종류(인사/직무)를 질문·답변 스크립트와 함께 휴대폰 내부에 저장하는 구성을 승인했다.
- 데이터 구조와 나머지 보관·백업 정책은 미정이다. 기록별 삭제와 삭제 전 확인 창은 이후 1.13과 같이 승인받았다.
- 데이터 모델·저장 파일 생성과 실제 저장·삭제 시험은 수행하지 않았다.

### 1.13 과거 기록 삭제 방식 승인 (2026-11-05)
- 사용자가 기록을 한 건씩 선택해 삭제하고, 삭제 전 확인 창을 표시하는 방식을 승인했다. 확인하면 해당 기록의 스크립트와 기본정보를 함께 삭제하고 취소하면 유지한다.
- 삭제 기능 구현, 확인 창 동작 시험, 실제 데이터 삭제는 수행하지 않았다. 일괄 삭제·자동 삭제·보관 기간·복구 기능·백업 정책은 미정이다.

### 1.14 무음 3초·종료 타이머·이어서 말하기 요구사항 (2026-11-05)
- 사용자가 답변 중 무음 기준을 3초로 지정하고, 답변 종료까지 남은 시간을 보여주는 타이머 애니메이션과 같은 답변을 계속할 수 있는 이어서 말하기 버튼을 요구했다.
- 다음 질문 준비·재생 중 이어서 말하기는 이후 1.15, 첫 발화 대기와 STT 단어 감지는 1.16과 같이 승인받았다. 카운트다운 중 버튼 사용 여부, STT 단어 판별·중간/확정 결과 처리와 무음 검출 방법은 미정이다.
- 음성·타이머·버튼 구현과 실제 동작 시험은 수행하지 않았다.

### 1.15 질문 준비·재생 중 이어서 말하기 동작 (2026-11-05)
- 사용자가 3초 이후 LLM의 다음 질문 준비 중이나 질문 음성 재생 중에도 이어서 말하기 버튼을 사용할 수 있도록 지정했다. 버튼 선택 시 준비·재생을 중단하고 직전 답변을 이어서 받은 뒤 전체 답변으로 다음 질문을 다시 검토한다.
- 질문 준비 취소·음성 중단·답변 재개·질문 재검토의 실제 동작과 재개한 답변의 무음 3초 처리는 향후 검증해야 한다. 구현과 실제 기기 시험은 수행하지 않았다.
- 첫 발화 대기와 STT 단어 감지는 이후 1.16, 중단된 질문의 문항 수 처리는 1.17, 스크립트 보관 방식은 1.18과 같이 승인받았다.

### 1.16 첫 발화 대기와 STT 단어 감지 기준 승인 (2026-11-05)
- 발화 시작은 STT가 새 발화에서 단어를 하나 이상 감지한 시점이다. 당초 승인한 첫 단어 무제한 대기는 이후 1.21의 무응답 7초 정책으로 변경했다. 이어서 말하기 후에도 같은 규칙을 적용하는 범위는 1.22와 같이 승인받았다.
- 재개 전 저장된 답변의 단어만으로는 이어 말하기의 시작으로 판단하지 않는다. 새 발화의 단어 감지 후 답변 중 무음 3초 기준을 적용한다.
- STT 단어 판별·중간/확정 결과 처리 방식과 무음 검출·인식 오류 처리는 미정이다. 실제 음성 시험이나 앱 구현은 수행하지 않았다.

### 1.17 중단된 질문의 문항 수 처리 승인 (2026-11-05)
- 사용자가 이어서 말하기로 중단된 다음 질문을 문항 수에서 제외하고, 다시 검토한 질문에 같은 문항 번호를 사용하는 방식을 승인했다.
- 질문 개수는 3~7문으로 조절하며 첫 사용 기본값은 5문이다. 중단된 질문의 스크립트 제외는 이후 1.18과 같이 승인받았다. 구체적인 문항 진행 구현은 미정이다.
- 문항 진행 코드 구현이나 실제 동작 시험은 수행하지 않았다.

### 1.18 최종 질문·전체 답변 스크립트 보관 승인 (2026-11-05)
- 사용자가 각 문항의 최종 질문과 기존 답변·추가 발화를 합친 전체 답변을 보관하고, 이어서 말하기로 중단된 질문은 과거 스크립트에서 제외하는 방식을 승인했다.
- 승인된 기본정보 저장 범위는 유지한다. 구체적인 데이터 구조와 저장 시점은 미정이다. 저장 기능 구현이나 실제 저장 시험은 수행하지 않았다.
- 마지막 답변 이후 평가 중 답변 재개는 이후 1.19와 같이 승인받았다.

### 1.19 마지막 답변 평가 중 이어서 말하기 승인 (2026-11-05)
- 사용자가 마지막 답변 평가 중 이어서 말하기를 제공하고, 선택하면 평가를 중단해 마지막 답변을 추가로 받은 뒤 전체 답변으로 다시 평가하는 방식을 승인했다.
- 재개한 발화에도 기존 STT 단어 감지 시작·무음 3초 기준을 적용한다. 결과 표시 이후 답변 재개 여부와 구체적인 평가 취소·재실행 방법은 미정이다.
- 앱 구현과 실제 평가 중단·발화 재개·재평가 시험은 수행하지 않았다. 점수 범위·소수점 사용은 이후 1.20, 가중치·제외 시 환산은 1.27, 답변 3항목의 문항별 점수 통합은 1.28과 같이 승인받았다. 시선·머리의 구간 비율·감점량은 승인받았으며 실제 기준점·화면 좌표 판정과 보정은 미정이다.

### 1.20 점수 범위·소수점 사용 승인 (2026-11-05)
- 사용자가 적용되는 각 평가 항목과 종합점수의 0~100점 범위를 승인하고 소수점 사용을 지정했다. 표시·반올림은 이후 1.25, 가중치·제외 시 환산은 1.27, 답변 3항목의 문항별 점수 통합은 1.28과 같이 승인받았다. 시선·머리의 구간 비율·감점량은 승인받았으며 실제 기준점·화면 좌표 판정과 보정은 미정이다.
- 점수 기능 구현이나 실제 채점 시험은 수행하지 않았다.

### 1.21 무응답 재질문·면접 종료 규칙 (2026-11-05)
- STT 시작 후 새 단어가 7초간 없으면 재질문하고, 재질문 후 STT 시작부터 다시 7초간 없으면 면접을 종료한다. 답변 시작 후 무음 3초와 구분하며 확인 창 표시 중 시간은 제외한다.
- 최신 1.45에 따라 이 종료는 평가·점수 산출 없이 끝낸다. 이전 미진행분 감점 요구사항은 대체했다. 재질문 문구·STT 오류와 무응답의 구분은 미정이다. 조기 종료 이력 미저장은 이후 1.46을 따르며 조기 종료 후 시작 화면 복귀는 이후 1.47을 따른다.

### 1.22 답변 재개 후 무응답 규칙 적용 승인 (2026-11-05)
- 새 질문과 이어서 말하기 모두 두 번의 7초 무응답 규칙을 동일하게 적용한다. 마지막 답변 평가를 중단한 뒤의 재개도 포함하며 기존 답변의 단어는 새 발화로 세지 않는다.
- 최신 1.45에 따라 두 번째 무응답 종료는 기존 완료 답변 수와 관계없이 평가·점수 산출 없이 끝낸다. 조기 종료 기록은 이후 1.46에 따라 저장하지 않으며 조기 종료 후 시작 화면 복귀는 이후 1.47을 따른다.

### 1.23 미진행분 기본 감점 계산 승인 (과거 결정, 1.45으로 대체)
> 적용 중단: 아래는 이전 승인 당시 기록이다. 현재 중도·자동 무응답 종료는 평가·점수 산출 없이 끝내며 아래 감점식·0점 처리를 적용하지 않는다. 현재 규칙은 1.45을 따른다.
- 사용자가 새 질문 미응답 종료 시 완료 문항 기준 감점 전 종합점수에 `완료 문항 수 / 설정 문항 수`를 곱하는 방식을 승인했다. 항목별 품질 점수는 유지하고 완료 0개면 최종 종합점수는 0점이다.
- 시선·머리의 구간 비율·감점량은 승인받았으며 실제 기준점·화면 좌표 판정과 보정은 미정이다. 이어서 말하기 실패의 추가 5점 감점과 기존 답변 완료 인정 유지는 이후 1.24, 표시·반올림은 1.25, 완료 문항 인정 기준은 1.26, 가중치·제외 시 환산은 1.27, 답변 3항목의 문항별 점수 통합은 1.28과 같이 승인받았다.
- 앱 구현이나 실제 채점 시험은 수행하지 않았다.

### 1.24 이어서 말하기 무응답 종료의 감점 승인 (과거 결정, 1.45으로 대체)
> 적용 중단: 아래는 이전 승인 당시 기록이다. 현재 중도·자동 무응답 종료는 평가·점수 산출 없이 끝내며 아래 감점식·0점 처리를 적용하지 않는다. 현재 규칙은 1.45을 따른다.
- 사용자가 기존 답변·완료 인정을 유지하고, 완료 비율을 반영한 종합점수에서 5점을 한 번 추가 감점하며 하한을 0점으로 두는 방식을 승인했다. 항목별 품질 점수는 유지한다.
- 새 질문 미응답 종료에는 1.23만 적용한다. 이 추가 감점은 이어서 말하기 후 재질문에도 무응답으로 종료한 경우에 적용한다.
- 앱 구현이나 실제 채점 시험은 수행하지 않았다. 소수점 표시·반올림은 이후 1.25와 같이 승인받았다.

### 1.25 점수 표시·반올림 승인 (2026-11-05)
- 사용자가 항목별 점수와 종합점수를 소수점 첫째 자리까지 표시하고, 둘째 자리에서 반올림하며 정수도 `80.0`처럼 표시하는 방식을 승인했다.
- 중간 계산값은 반올림하지 않고 화면 표시 시에만 반올림한다. 숫자 자료형과 실제 구현은 미정이며, 실제 표시 시험이나 앱 구현은 수행하지 않았다.
- 완료 문항의 일반 인정 기준은 이후 1.26과 같이 승인받았다.

### 1.26 완료 문항 인정 기준 승인 (2026-11-05)
- 사용자가 STT가 새 단어를 하나 이상 감지해 답변이 시작되고 이후 무음 3초로 답변이 종료된 문항을 완료로 세는 방식을 승인했다. 같은 문항을 이어서 말해도 한 문항으로 집계하며 답변 품질은 항목별 점수에서 평가한다.
- 이어서 말하기 실패 시 기존 답변·완료 인정 유지와 중단 질문의 문항 수 제외도 따른다. 상세 기준은 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.11을 따른다.
- 문항 상태와 실제 구현은 미정이며 앱 구현이나 실제 문항 집계·답변 재개 시험은 수행하지 않았다.
- 인사·직무 공통 가중치와 두 움직임 항목 제외 시 비중 재분배는 이후 1.27과 같이 승인받았다.

### 1.27 평가 항목별 가중치·제외 시 환산 승인 (2026-11-05)
- 정상 완료 면접은 구성 25·논리력 30·현실성 25·시선 10·머리 10의 가중합을 적용 비중 합계로 나눈다. 두 움직임 항목 제외 시 답변 가중합을 80으로 나눈다. 최종 표시 시에만 반올림한다.
- 중도·자동 무응답 종료는 최신 1.45에 따라 점수를 산출하지 않는다. 상세 정상 완료 계산은 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.12·4.13을 따른다. 실제 AI 평가 품질은 미검증이다.

### 1.28 답변 문항별 점수 통합 승인 (2026-11-05)
- 정상 완료 면접은 완료 문항별 구성·논리력·현실성을 동일 비중으로 평균하며 원래 답변과 추가 발화를 문항당 한 번 포함한다. 미완료 문항을 0점으로 평균에 넣지 않는다.
- 중도·자동 무응답 종료는 완료 0개를 포함해 평가·점수를 산출하지 않으며 기존 0점 대체는 적용을 중단한다. 상세 기준은 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.13·4.30을 따른다.

### 1.29 답변의 구성 채점 기준 승인 (2026-11-05)
- 사용자가 핵심 제시·정보 순서·내용 집중·마무리를 같은 비중으로 평가하고, 기준마다 미충족 0점·부분 충족 1점·충족 2점을 부여해 `합계 ÷ 8 × 100`으로 문항별 구성 점수를 구하는 방식을 승인했다.
- 기존·추가 발화를 합친 전체 답변을 평가하며 답변 길이와 형식은 자유롭게 둔다. 완료 문항 평균과 표시 시 반올림은 기존 승인을 따른다. 상세 기준은 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.14를 따른다.
- 실제 AI 평가 방식과 세부 판정 기준의 검증은 미정이며 앱 구현이나 실제 채점·평가 품질 시험은 수행하지 않았다.
- 논리력 채점 기준은 이후 1.30, 현실성 채점 기준은 1.31과 같이 승인받았다. 시선·머리 채점은 별도 논의가 필요하다.

### 1.30 답변의 논리력 채점 기준 승인 (2026-11-05)
- 사용자가 근거 제시·근거와 결론의 연결·같은 답변 안의 일관성·비약 억제를 같은 비중으로 평가하고, 기준마다 미충족 0점·부분 충족 1점·충족 2점을 부여해 `합계 ÷ 8 × 100`으로 문항별 논리력 점수를 구하는 방식을 승인했다.
- 기존·추가 발화를 합친 전체 답변을 평가하며 완료 문항 평균과 표시 시 반올림은 기존 승인을 따른다. 상세 기준은 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.15를 따른다.
- 다른 문항 간 진술 비교·사실 확인·실제 AI 평가 방식은 미정이며 앱 구현이나 실제 채점·평가 품질 시험은 수행하지 않았다.
- 현실성 채점 기준은 이후 1.31과 같이 승인받았다. 사실 확인·직무 지식 검증·기준 자료 확보는 별도 논의가 필요하다.

### 1.31 답변의 현실성 채점 기준 승인 (2026-11-05)
- 사용자가 구체성·실행 가능성·직무와 상황 적합성·결과의 개연성을 같은 비중으로 평가하고, 기준마다 미충족 0점·부분 충족 1점·충족 2점을 부여해 `합계 ÷ 8 × 100`으로 문항별 현실성 점수를 구하는 방식을 승인했다.
- 기존·추가 발화를 합친 전체 답변을 평가하며 완료 문항 평균과 표시 시 반올림은 기존 승인을 따른다. 상세 기준은 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.16을 따른다.
- 질문 유형별 세부 판정·직무와 회사의 사실 확인·경험의 진위 확인·기준 자료 확보·실제 AI 평가 방식은 미정이며 앱 구현이나 실제 채점·평가 품질 시험은 수행하지 않았다.
- 시선·머리 채점에 제안했던 답변 구간 한정안은 이후 사용자가 지정한 전 구간 채점으로 대체했다. 현재 범위는 1.32를 따른다.

### 1.32 시선·머리 움직임 전 구간 채점 지정 (2026-11-05)
- 사용자가 시선·머리 움직임을 면접 시작부터 결과 표시 직전까지 전 구간에 대해 채점하도록 지정했다. 질문 준비·재생, 첫 단어·무응답 대기, 재질문, 답변·무음, 이어서 말하기 전후와 평가 대기도 포함한다. 이후 1.44에 따라 종료 확인 창 표시 시간은 관찰·채점·추적 누락 집계에서 제외한다.
- 면접 시작 전 준비 화면과 결과 표시 이후는 범위 밖이다. STT 단어 감지·무음 3초로 움직임 채점 범위를 제한하지 않는다. 상세 범위는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.17을 따른다. 카메라 오류·TrueDepth 미지원 시 두 항목 제외, 과거 이력에 원본 관찰 자료를 저장하지 않는 기존 요구사항은 유지한다.
- 채점 진행 방식은 이후 1.33과 같이 사용자가 지정했으며 구간 비율·감점량은 이후 1.36·1.37과 같이 승인받았다. 실제 기준점·좌표 보정·실패 판별 기준·구현은 미정이며 준비 화면과 면접 도중 추적 어려움의 처리는 1.38·1.39의 승인된 규칙을 따른다. 앱 구현이나 실제 관찰·채점 시험은 수행하지 않았다.
- 전체 관찰 자료의 항목별 점수 산출 제안은 이후 1.33에서 사용자가 직접 지정한 채점 진행 방식으로 구체화했다.

### 1.33 시선·머리 초당 중앙 확인·누적 감점 지정 (2026-11-05)
- 사용자가 시선·머리가 각각 중앙에 위치하는지 초당 한 번 확인하고, 두 항목을 각각 100점으로 시작해 중앙을 벗어날 때마다 조금씩 감점하도록 지정했다. 기존 전 구간 채점과 0~100점 범위를 따른다. 상세 범위는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.18을 따른다.
- 단계별 감점량·구간 경계는 이후 1.36·1.37과 같이 승인받았다. 실제 기준점·좌표 보정·추적 실패 판별 기준·안내 표시 방식·카메라 및 추적 설정은 미정이며 준비 화면과 면접 도중 추적 어려움의 처리는 1.38·1.39의 승인된 규칙을 따른다. 연속 이탈 시 감점 집계는 이후 1.34와 같이 매 확인마다 감점하도록 확인받았다.
- 앱 구현이나 실제 중앙 판정·관찰·채점 시험은 수행하지 않았다. 실제 기기에서의 정확도·부하 검증도 미실시다.

### 1.34 매초 중앙 이탈 감점·공동 채점 설정 지정 (2026-11-05)
- 사용자가 매초 확인에서 중앙 이탈을 감지할 때마다 해당 항목을 감점하도록 확인했다. 연속 5회 감지되면 5회 감점한다. 이후 1.36에서 지정한 단계별 감점량에 따라 `항목 점수 = max(0, 100 − 해당 항목의 매 확인별 감점량 합계)`로 누적한다.
- 사용자가 시선·머리 채점 포함 여부를 설정에서 함께 선택하는 방식을 지정했다. 설정 하나로 함께 켜고 끄며 점수는 각각 유지한다. 꺼진 두 항목은 평가·종합점수에서 제외하고 기존 적용 비중 환산식을 따른다. 켜져 있어도 기기 제외 조건을 따른다. 상세 범위는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.18·4.19를 따른다.
- 면접 시작 후 설정 변경 제한은 이후 1.42를 따른다. 설정 저장·비활성 시 카메라 운용과 실제 구현은 미정이다. 앱 구현이나 실제 설정·채점 시험은 수행하지 않았다.
- 첫 사용 기본값 켜짐은 이후 1.35와 같이 승인받았다. 단계별 구간 경계는 이후 1.37과 같이 승인받았으며 실제 화면 좌표 판정과 보정은 별도 논의가 필요하다.

### 1.35 시선·머리 공동 채점 설정 기본값 승인 (2026-11-05)

### 1.36 시선·머리 이탈 정도별 감점 지정 (2026-11-05)

### 1.37 중앙 영역·감점 구간 경계 승인 (2026-11-05)

- 승인 범위는 영역의 비율·모양·경계 포함 방식이다. 실제 시선·머리 기준점·화면 좌표 변환·보정·기기 판정 정확도·추적 실패 판별은 미정·검증 전이며 앱 구현이나 실제 관찰·판정·채점 시험은 수행하지 않았다.

- 앱 구현이나 실제 조명 조건별 추적·안내·평가 제외 시험은 수행하지 않았다. 새 실행·빌드·테스트 명령이나 저장 정책은 정하지 않았다.

검증 도구는 소스와 시험의 사본으로 임시 디렉터리에만 Swift 패키지를 만든다. 저장소·전역 경로에 패키지를 설치하지 않는다. 현재 Xcode 27.2·Swift 6.4.2로 질문 설정·점수·움직임·면접 진행·종료 확인 정지/취소 재개 시험 함수 48개(매개변수 사례 포함)가 통과했다. 핵심 값 형식에 `nonisolated`를 명시해 Xcode의 기본 MainActor 설정과 무관하게 시험할 수 있도록 했으며, 기본 설정과 MainActor 설정 양쪽에서 iOS 26 소스 검사를 수행한다. MainActor는 화면 처리를 직렬로 수행하는 실행 영역이다. iOS 26 배포 대상의 소스 검사는 실제 앱의 링크·실행 검증과 구분한다. 사건·시간은 시험에서 입력하며 질문 준비·재생·평가·음성 인식 지시는 실제 장치를 실행하지 않는다. 이전 절의 미실시 기록은 각 승인 당시 상태다. 확인 창의 표시 시간 제외·남은 시간 보존·이전 자료 차단을 합성 입력으로 검증했다. 최신 무응답 무평가 종료·완료 수와 관계없는 점수 미생성·이전 결과/관찰 차단도 검증했다. 9개 진행 단계의 확인 종료·잘못된/이전 확인 번호 거부·취소 후 정상 완료도 검증했다. 실제 장치 작업 중단·이력 저장·화면 이동은 미구현이다. 이전 방법은 [INTEGRATION.md](../../ios_temp/INTEGRATION.md)를 따른다.
