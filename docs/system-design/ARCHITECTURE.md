## 1. 개요
<!-- 이 시스템이 무엇을 하는지 2~3줄. 어디까지가 이 저장소의 책임이고 무엇이 바깥(외부 API, 기존 서비스)인지. -->
就活一歩는 혼자서 면접을 연습하고 취업활동을 관리하기 위한 iOS 전용 앱이다.
화면 언어는 일본어이며 일본에만 출시할 예정이다. 서버는 가능하면 사용하지 않되, 사용 여부는 미정이다.
최소 iOS 버전은 26.0, 로컬 저장 도구는 SwiftData로 승인받았다. SwiftData의 CloudKit 자동 동기화는 비활성화한다. 나머지 기술 스택과 데이터 구조는 사용자 승인 후 결정한다.
정식 출시 때는 가능하다면 iPhone 13 이상을 지원하는 것이 사용자 목표다. 실제 지원 범위는 기기·성능 검증 후 결정한다.

### 1.1 모의면접 구성
- 사용자는 회사명, 업종(예: 금융·IT·보육), 직무(예: 상담원·테스터), 면접 종류(인사/직무)를 선택하고 모의면접을 시작한다.
- 질문 개수의 앱 첫 사용 기본값은 5문이며, 설정 등의 메뉴에서 3~7문으로 조절한다. 설정 화면의 구체적인 배치와 설정값 저장 방식은 미정이다.
- 인사면접은 성격, 가치관, 협업, 지원 동기를 평가한다.
- 직무 면접은 선택한 직무에 대한 실무 지식, 문제 해결 능력, 직무 전문성 등을 평가한다.
- AI가 질문을 진행하며, 이어서 말하기로 보완된 전체 답변을 반영해 다음 질문을 다시 검토한다. 질문 구성·선정의 구체적인 방법과 제품 최종 AI 처리 위치는 미정이다.

### 1.2 평가 항목과 시점
| 평가 항목 | 관찰·평가 시점 | 적용 조건 |
|---|---|---|
| 답변의 구성 | 정상 완료 후 | 기본 평가 항목 |
| 답변의 논리력 | 정상 완료 후 | 기본 평가 항목 |
| 답변의 현실성 | 정상 완료 후 | 기본 평가 항목 |
| 시선의 움직임 | 면접 중 실시간 관찰 | 공동 설정 켜짐·전면 카메라 정상 동작·TrueDepth 지원·준비 화면 추적 가능 시 |
| 머리의 움직임 | 면접 중 실시간 관찰 | 공동 설정 켜짐·전면 카메라 정상 동작·TrueDepth 지원·준비 화면 추적 가능 시 |

- 정해진 계산식으로 각 항목과 종합평가 점수를 산출한다. 적용되는 각 평가 항목과 종합점수는 0~100점 범위이며 소수점 한 자리로 표시한다. 둘째 자리에서 반올림은 화면 표시 시에만 적용하고 중간 계산값은 반올림하지 않는다. 정상 완료 종합점수는 인사·직무 공통으로 구성 25·논리력 30·현실성 25·시선 10·머리 10의 비중으로 가중합을 구해 적용 비중 합계로 나눈다. 답변 3항목은 완료 문항별 점수를 같은 비중으로 단순 평균한다. 시선·머리의 구간 비율·감점량은 승인받았으며 실제 기준점·화면 좌표 판정과 보정은 미정이다.
- 구성 점수는 문항마다 핵심 제시·정보 순서·내용 집중·마무리를 각각 0·1·2점으로 평가해 `합계 ÷ 8 × 100`으로 환산한다. 네 기준은 같은 비중이며 답변 길이와 형식은 자유롭게 둔다. 상세 승인 범위는 6.35를 따른다.
- 논리력 점수는 문항마다 근거 제시·근거와 결론의 연결·같은 답변 안의 일관성·비약 억제를 각각 0·1·2점으로 평가해 `합계 ÷ 8 × 100`으로 환산한다. 네 기준은 같은 비중이며 전체 답변을 한 번 평가해 완료 문항 평균을 적용한다. 상세 승인 범위는 6.36을 따른다.
- 현실성 점수는 문항마다 구체성·실행 가능성·직무와 상황 적합성·결과의 개연성을 각각 0·1·2점으로 평가해 `합계 ÷ 8 × 100`으로 환산한다. 네 기준은 같은 비중이며 전체 답변을 한 번 평가해 완료 문항 평균을 적용한다. 상세 승인 범위는 6.37을 따른다.
- 시선·머리 움직임은 면접 시작부터 결과 표시 직전까지 전 구간을 채점하되 6.50의 종료 확인 창 표시 시간은 제외한다. 질문 준비·재생·무응답 대기·재질문·답변·이어서 말하기·평가 대기를 포함하며 STT 단어 감지나 무음 3초로 채점 구간을 제한하지 않는다. 상세 범위는 6.38을 따른다.
- 시선·머리가 중앙에 위치하는지 각각 초당 한 번 확인한다. 두 항목은 각각 100점으로 시작해 매 확인마다 조금 이탈 0.1점·큰 이탈 0.2점·화면 끝쪽 근처 0.3점·화면 밖 0.4점의 해당 단계 감점량을 누적한다. 중앙 50%·70%·90%의 중첩 사각 영역과 경계 포함 방식은 승인받았다. 상세 범위는 6.39·6.40·6.42·6.43을 따른다. 실제 기준점·화면 좌표 변환과 보정·추적 실패 판별은 미정이다.
- 설정 하나로 시선·머리 채점을 함께 켜고 끄며, 꺼진 항목은 기존 적용 비중 환산식에 따라 종합점수에서 제외한다. 평가 가능한 기기에서 첫 사용 기본값은 켜짐이다. 상세 범위는 6.40·6.41을 따른다.
- 전면 카메라가 정상적으로 동작하지 않거나 TrueDepth를 지원하지 않는 기기에서는 시선·머리 움직임을 모두 채점 항목과 종합점수 계산에서 제외한다. 해당 항목을 0점으로 처리하지 않는다.
- 준비 화면에서 조명 등으로 추적이 어려우면 확인 메시지를 표시하고 시선·머리 평가를 모두 제외한다. 답변 3항목의 비중 합계 80으로 환산하며 상세 요구사항은 6.44를 따른다.
- 면접 도중 시선·머리 중 하나라도 정상 추적 자료를 3초 연속 얻지 못하면 안내 후 면접을 계속하고 그 면접의 시선·머리 평가 전체를 제외한다. 앞서 누적된 움직임 감점도 종합점수에서 제외하며 상세 승인 범위는 6.45를 따른다.
- 결과 화면에서 제외된 시선·머리 항목에는 숫자 점수 대신 평가 제외 상태와 이유를 표시한다. 상세 승인 범위는 6.46을 따른다.
- 인사/직무 면접별 평가 관점을 위 공통 채점 항목에 어떻게 반영할지는 미정이다.

<!-- 가장 대표적인 요청·동작 1~2개를 단계별로. 이 흐름을 따라가면 코드 구조가 이해되는 것으로 고른다. -->
### 6.1 모의면접 시작부터 결과 확인까지
1. 사용자가 회사명·업종·직무·면접 종류를 선택한다. 질문 개수는 설정 등의 메뉴에서 지정한 3~7문을 사용한다.
2. 준비 화면에서 시선·머리 움직임을 정확하게 관찰할 수 있는 거리인지 확인한다.
3. 전면 카메라 동작과 TrueDepth 지원 여부를 확인한다. 둘 중 하나라도 충족하지 않으면 시선·머리 움직임을 채점 및 종합점수 계산에서 제외한다. 준비 화면에서 조명 등으로 추적이 어려운 경우에도 확인 메시지를 표시하고 두 항목을 제외한다.
4. AI가 질문을 TTS(문자를 음성으로 읽는 기능)로 읽는다.
5. 질문이 끝나면 사용자 차례가 된다. STT(음성을 문자로 바꾸는 기능)가 새 발화에서 단어를 하나 이상 감지하면 발화 시작으로 판단하고, 사용자의 말을 화면에 표시한다. STT 시작 후 7초간 단어가 없으면 재질문하고, 재질문 후 STT 시작부터 다시 7초간 단어가 없으면 평가·점수 산출 없이 면접을 종료한다. 이어서 말하기 후에도 같은 7초 규칙을 적용한다.
6. 답변이 시작된 뒤 3초간 연속 무음이면 답변 종료로 판단한다. 종료까지 남은 시간을 타이머 애니메이션으로 표시한다. 다음 질문 준비·재생 중에도 이어서 말하기를 선택할 수 있으며, 선택하면 준비·재생을 중단하고 직전 답변을 이어서 받은 후 전체 답변으로 다음 질문을 다시 검토한다.
7. 설정한 질문 개수만큼 질문과 답변을 반복한다. 이어서 말하기로 중단된 다음 질문은 문항 수에서 제외하고, 다시 검토한 질문에 같은 문항 번호를 사용한다. 시선·머리 움직임 평가가 가능한 경우 면접 중 실시간으로 관찰한다.
8. 설정 문항을 정상 완료한 경우 답변의 구성·논리력·현실성을 평가한다. 평가 중 이어서 말하기를 선택하면 평가를 중단하고 마지막 답변을 추가로 받은 뒤 전체 답변으로 다시 평가한다. 평가 완료 후 종합평가 점수·각 항목별 점수·질문 및 답변 스크립트를 표시한다.

사용자가 진행 중인 모의면접을 직접 종료하려 하면 확인 창을 표시한다. 종료 확인 후에만 종료하며 취소하면 면접을 유지한다. 확인 창 표시 중에는 6.50과 같이 모두 정지한다. 종료 후 평가·점수는 산출하지 않고 조기 종료 이력은 저장하지 않는다. 조기 종료 후에는 6.53에 따라 시작 화면으로 돌아가며, 확인 절차의 상세 승인 범위는 6.49를 따른다.

### 6.2 과거 모의면접 확인
1. 과거 모의면접은 질문·답변 스크립트와 면접 시작 일시·회사명·업종·직무·면접 종류(인사/직무)를 휴대폰 내부에 저장한다.
   각 문항의 최종 질문과 기존 답변·추가 발화를 합친 전체 답변을 보관하고, 이어서 말하기로 중단된 질문은 스크립트에서 제외한다.
2. 과거 기록을 면접 시작 일시 기준 최신순으로 표시하며, 사용자는 저장된 과거 모의면접 스크립트를 다시 확인할 수 있다.
3. 사용자는 기록을 한 건씩 선택해 삭제할 수 있다. 삭제 전 확인 창에서 삭제를 확인하면 해당 기록의 스크립트와 기본정보를 함께 삭제하고, 취소하면 유지한다.

### 6.3 논의가 필요한 사항
- AI의 질문 구성·선정 및 답변 평가 방식, 기기 내부/외부 처리 여부, 서버 사용 여부
- 시선·머리의 기준점·화면 좌표 판정과 보정·공동 채점 설정 저장·잠금 표시·사용자 종료의 세부 흐름·정상 추적 자료의 품질 판별·누락/회복 감지·시간 측정·안내 표시 방식·제외 후 추적 운용. 화면 영역 비율·경계 포함 방식은 6.43과 같이 승인받음
- STT 단어 판별·중간/확정 결과 처리, 무음 검출과 인식 오류 처리, 카운트다운 중 이어서 말하기, 결과 화면 표시 이후 답변 재개 여부
- 적정 거리·관찰 품질 기준, 준비 화면의 최종 일본어 확인 메시지·버튼·확인 후 흐름·재확인 기능, 권한 거부 시 처리
- 스크립트·승인된 기본정보의 구체적인 데이터 구조와 과거 기록의 표시·추가 보관·백업 정책
- 취업활동 관리 기능의 구체적인 범위

### 6.4 기기 내부 일본어 LLM 가능성 조사 (2026-11-05)
사용자는 가능하면 매우 가벼운 일본어 LLM을 휴대폰 내부에서 실행하기를 원한다. 첫 검증 모델은 이후 LFM2.5-1.2B-JP-202606(6.7), 검증용 실행 도구는 MLX Swift LM(6.8)으로 승인받았다. 제품 최종 모델, 실행 도구의 버전·연동 설정, 최소 지원 기기, 서버 사용 여부는 확정하지 않았다. 외부 전송 허용 여부도 여전히 미정이다.

기기 내부에서 LLM을 실행하는 선택지는 존재한다. 아래 내용은 공식 자료 조사 결과이며, 실제 iPhone에서 이 앱의 성능·채점 품질을 검증한 결과는 아니다.

| 검토 후보 | 공식 자료에서 확인한 내용 | 이 앱에서 추가로 확인할 사항 |
|---|---|---|
| [LFM2.5-1.2B-JP-202606](https://huggingface.co/LiquidAI/LFM2.5-1.2B-JP-202606) | 약 11.7억 매개변수의 일·영 텍스트 모델. 기기 내부 비서와 구조화 출력 등이 권장 용도이며, 지식 집약적 작업은 비권장 | 일본어 면접 답변의 구성·논리력·현실성 및 직무 지식 판단 품질 |
| [Apple Foundation Models의 기기 내부 모델](https://developer.apple.com/foundation-models-framework/) | Apple Intelligence의 기기 내부 모델을 앱에서 사용해 인터넷 없이 처리 가능. 현재 프레임워크에는 클라우드 모델도 있으므로 기기 내부 모델을 명시적으로 구분해야 함 | [지원 기기·언어 조건](https://support.apple.com/en-gb/121115) 및 [실행 시 모델·언어 가용성](https://developer.apple.com/documentation/foundationmodels/supporting-languages-and-locales-with-foundation-models), 일본어 면접 평가 품질 |
| [Qwen3.5-0.8B](https://huggingface.co/Qwen/Qwen3.5-0.8B) / [2B](https://huggingface.co/Qwen/Qwen3.5-2B) | 8억/20억 매개변수 규모의 공개 모델. [공식 언어 목록](https://qwen.ai/blog?id=qwen3.5)에 일본어 포함. 0.8B는 제작사가 시제품·작업별 미세조정·연구개발 용도를 명시 | 작은 크기만으로 일본어 면접 채점 품질을 보장할 수 없으며, 실행 도구와 iPhone 성능 검증 필요 |

용량은 실행 시 메모리 사용량과 구분한다. Liquid AI가 공개한 LFM2.5-1.2B-JP-202606의 [MLX 4비트 가중치 파일은 692 MB](https://huggingface.co/LiquidAI/LFM2.5-1.2B-JP-202606-MLX-4bit/tree/main), [GGUF Q4_K_M 파일은 731 MB](https://huggingface.co/LiquidAI/LFM2.5-1.2B-JP-202606-GGUF/tree/main)이다. 4비트 양자화는 모델의 수치 표현을 줄여 용량을 낮춘 형식이다. 실행에는 대화 내용과 작업 공간 등을 위한 추가 메모리가 필요하므로 파일 크기를 필요 RAM으로 간주하지 않는다. 모델을 다운로드하거나 설치하지 않았다.

조사에서 제시한 안과 후속 승인 상태:
- 첫 검증 모델 선정은 6.7에서 승인받았다. Apple 모델 또는 Qwen을 추가 비교할지와 제품 최종 모델은 미정이다.
- LLM에 근거와 평가 항목을 추출하게 하고, 확정된 계산식의 합산은 앱 코드에서 처리하는 방식을 검토한다. 이 경우에도 LLM의 항목별 판단이 일관적인지는 따로 검증해야 한다.
- 상세 직무 지식을 모델 자체의 기억에만 의존하지 않도록, 직무별 기준 답안·채점 기준을 함께 제공하는 방식을 검토한다.
- 실제 iPhone에서 일본어 답변의 품질과 채점 일관성, 대기 시간, 메모리, 발열을 확인한다. 3문·7문과 카메라 관찰·음성 처리까지 포함한 전체 흐름 검증이 필요하다.
- STT는 이후 SpeechAnalyzer + SpeechTranscriber의 기기 내부 처리, TTS는 AVSpeechSynthesizer로 승인받았다. 초기 모델 배포/다운로드 방식은 미정이다. 완전한 오프라인 동작과 서버 미사용은 아직 확정하지 않는다.

### 6.5 보유 테스트 기기에 따른 검토 조건 (2026-11-05)
- 사용자는 iPhone 14 Plus와 iPhone XR을 테스트에 사용할 수 있다. 사양과 설치된 OS 확인 상태는 [OPERATIONS.md](OPERATIONS.md)의 테스트 기기 표를 따른다. 이후 사용자가 정한 출시 지원 목표는 가능하다면 iPhone 13 이상이며, 보유 기기 목록과 출시 지원 범위를 구분한다.
- 두 기기는 [Apple Intelligence 지원 대상](https://support.apple.com/en-gb/121115)이 아니므로 Apple의 기기 내장 모델을 직접 시험할 수 없다. 별도 경량 모델을 앱에서 실행하는 방식은 계속 검토할 수 있으며, 보유 기기에서의 호환성·성능을 보장하는 것은 아니다.
- 현재 [MLX Swift](https://github.com/ml-explore/mlx-swift/blob/main/Package.swift)와 [MLX Swift LM](https://github.com/ml-explore/mlx-swift-lm/blob/main/Package.swift)의 패키지에는 iOS 17이 최소 OS로 선언되어 있다. 이는 특정 모델의 XR 실행 보장이 아니며, Foundation Models 연동 등 일부 기능에는 더 높은 OS 조건이 있다. 검증용 실행 도구는 MLX Swift LM으로 승인받았고, 사용할 버전·연동 설정과 기기 호환성은 별도 확인이 필요하다.
- 이후 최소 iOS 26 이상을 승인받아 XR은 앱 설치 대상에서 빠진다. 14 Plus의 실제 OS 버전과 시험 순서는 아직 확인·확정하지 않았다.
- 출시 지원 목표는 가능하다면 iPhone 13 이상이다. 첫 검증 모델은 LFM2.5-1.2B-JP-202606, 검증용 실행 도구는 MLX Swift LM, 최소 iOS 버전은 26.0으로 승인받았다. 제품 최종 모델, 실행 도구의 버전·연동 설정과 서버 사용 여부는 미정이다.

### 6.6 iPhone 13 이상 출시 지원 목표 (2026-11-05)
- 사용자는 가능하다면 iPhone 13 이상을 지원하고 싶다고 밝혔다. 이는 조건부 목표이며 검증을 마친 지원 약속으로 해석하지 않는다.
- 목표의 기준 기기인 [iPhone 13](https://support.apple.com/en-ie/111872)은 TrueDepth 카메라를 탑재하지만 [Apple Intelligence 지원 기기](https://support.apple.com/en-gb/121115)에는 포함되지 않는다. 따라서 Apple 내장 LLM만으로 목표 기기의 AI 기능을 제공하는 방식은 이 목표를 충족하지 못한다.
- 별도 경량 일본어 LLM을 기기 내부에서 실행하는 안은 계속 검토한다. 제품 최종 모델 채택이나 서버 미사용을 확정한 것은 아니다.
- 14 Plus와 iPhone 13은 같은 A15 Bionic 이름을 사용하지만 GPU 구성이 다르다. 현재 보유 기기의 시험 결과만으로 iPhone 13의 지연 시간·메모리·발열과 전체 면접 흐름을 검증했다고 간주하지 않는다. 자세한 시험 환경과 미확인 항목은 [OPERATIONS.md](OPERATIONS.md)를 따른다.

### 6.7 첫 검증 LLM 선정 승인 (2026-11-05)
- 사용자는 LFM2.5-1.2B-JP-202606을 첫 검증 대상으로 선정하는 안을 명시적으로 승인했다.
- 일본어 면접 평가 품질, 응답 시간, 메모리 사용량, 발열을 확인한 뒤 제품 최종 채택 여부를 함께 결정한다. 수치로 된 합격 기준과 검증 자료는 미정이다.
- 이때의 승인은 검증 모델 선정에 적용되며, 검증용 실행 도구는 이후 6.8, 최소 iOS 버전은 6.9에서 추가 승인받았다. 압축 형식, 앱 구성, 서버 사용 여부와 외부 전송 허용 여부는 미정이다.
- 모델 다운로드·설치, 검증 앱 구현, 실제 기기 시험은 아직 수행하지 않았다.

### 6.8 검증용 실행 도구 선정 승인 (2026-11-05)
사용자가 MLX Swift LM을 검증용 모델 실행 도구로 승인했다. 아래 표는 선정 과정에서 비교한 도구의 근거이며, llama.cpp의 추가 도입이나 비교 시험은 승인받지 않았다.

### 6.9 최소 iOS 버전 승인 (2026-11-05)
사용자가 최소 iOS 26 이상을 승인했다. 이는 앱을 설치할 수 있는 OS의 하한이며, iPhone 13 이상이라는 조건부 하드웨어 지원 목표와 구분한다. 아래는 결정 전에 비교한 안이다.

| 검토안 | 근거와 의미 | 영향 |
|---|---|---|
| iOS 26 이상 | iOS 26에서 도입한 [SpeechAnalyzer](https://developer.apple.com/videos/play/wwdc2025/277/)를 통해 기기 내부 음성 인식을 검토할 수 있음. [iOS 26 호환 기기](https://support.apple.com/en-ie/guide/iphone/-iphe3fa5df43/ios)에 iPhone 13과 14 Plus가 포함됨 | 지원 기기도 OS 업데이트가 필요하며, XR에는 설치할 수 없음 |
| iOS 17 이상 등 더 낮은 OS 하한 | MLX Swift LM 핵심 패키지의 OS 선언은 iOS 17부터이며, 구버전 OS 사용자까지 검토할 여지가 있음 | iOS 26 전용 음성 인식 API를 쓰려면 별도 구버전 처리 경로 또는 다른 음성 인식 도구를 검토해야 함 |

실시간 음성 인식과 기기 내부 처리를 고려해 제안한 iOS 26 이상을 최소 버전으로 확정했다. 음성 인식 도구는 이후 6.10에서 승인받았으며, 지원되지 않을 때의 처리는 미정이다. [Apple의 안내](https://developer.apple.com/forums/thread/802863)에 따라 기기 지원은 실행 시 확인하고, 일본어 지원·모델 설치 상태·실제 인식 품질도 검증해야 한다. XR은 설치 대상에 포함되지 않는다. 앱 프로젝트와 빌드 설정은 아직 생성하지 않았다.

### 6.10 음성 인식 도구 선정 승인 (2026-11-05)
- 사용자가 Apple의 [SpeechAnalyzer와 SpeechTranscriber](https://developer.apple.com/videos/play/wwdc2025/277/)를 기기 내부 음성 인식(STT) 도구로 승인했다. 전자는 음성 분석 세션을 관리하고, 후자는 음성을 문자로 변환한다.
- Apple은 이 조합의 기기 내부 처리, 실시간 중간 결과 표시와 긴 대화의 문자 변환을 설명한다. 실제 면접에서의 일본어 정확도와 지연 시간은 시험해야 한다.
- [SpeechTranscriber 문서](https://developer.apple.com/documentation/speech/speechtranscriber)에 따라 기기 지원 여부와 지원·설치된 언어를 확인한다. 일본어 지원 가능 여부를 실기기에서 검증하기 전에는 지원을 보장하지 않는다.
- [AssetInventory](https://developer.apple.com/documentation/speech/assetinventory)를 통해 필요한 언어 모델을 Apple 서버에서 다운로드·설치한 뒤 기기 내부에서 처리한다. 다운로드 시점과 안내 방식은 아직 결정하지 않았다.

### 6.12 시선·머리 움직임 관찰 기술 선정 승인 (2026-11-05)

- 초당 중앙 확인·각각 100점 시작·누적 감점 방식은 이후 6.39와 같이 사용자가 지정했다. 단계별 감점량·구간 비율은 이후 6.42·6.43과 같이 승인받았다. 실제 기준점·화면 좌표 판정과 보정·추적 실패 판별 기준은 미정이다. 준비 화면의 추적 어려움은 6.44, 면접 도중 추적 불가는 6.45의 승인된 규칙을 따른다. 원본 영상·움직임 데이터를 과거 면접 이력으로 저장하는 기능은 추가하지 않는다.

### 6.14 테스트 구성 선정 승인 (2026-11-05)

|---|---|---|
| Swift Testing | 개별 기능의 계산·판정 로직 및 코드 간 연결 검증 | 채점 계산식, 시선·머리 항목 제외 시 계산, 3~7문 범위, 무음에 따른 답변 완료와 면접 진행 상태 |

### 6.29 미진행분 기본 감점 계산 승인 (과거 결정, 6.51으로 대체)
> 적용 중단: 아래는 이전 승인 당시 기록이다. 현재 중도·자동 무응답 종료는 평가·점수 산출 없이 끝내며 아래 감점식·0점 처리를 적용하지 않는다. 현재 규칙은 6.51을 따른다.
사용자가 새 질문 미응답 종료 시 `최종 종합점수 = 완료 문항 기준 감점 전 종합점수 × 완료 문항 수 ÷ 설정 문항 수`로 계산하는 방식을 승인했다. 항목별 점수는 품질 평가 점수로 유지하고, 미진행분 감점은 종합점수에 반영한다. 완료 문항이 0개면 최종 종합점수는 0점이다. 시선·머리의 구간 비율·감점량은 승인받았으며 실제 기준점·화면 좌표 판정과 보정은 미정이다. 또한 완료 문항 인정 기준은 이후 6.32, 가중치·제외 시 환산은 6.33, 답변 3항목의 문항별 점수 통합은 6.34와 같이 승인받았다. 자세한 범위는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.8을 따른다. 앱 구현이나 실제 채점 시험은 수행하지 않았다.

### 6.30 이어서 말하기 무응답 종료의 감점 승인 (과거 결정, 6.51으로 대체)
> 적용 중단: 아래는 이전 승인 당시 기록이다. 현재 중도·자동 무응답 종료는 평가·점수 산출 없이 끝내며 아래 감점식·0점 처리를 적용하지 않는다. 현재 규칙은 6.51을 따른다.

### 6.50 종료 확인 창 표시 중 전체 정지 지정 (2026-11-05)
사용자가 종료 확인 창이 떠 있는 동안 모두 정지하도록 지정했다. 면접 단계·전환, AI 질문 생성·답변 평가 및 결과 반영, 음성 재생·인식, 무음 3초·무응답 7초·타이머 애니메이션뿐 아니라 시선·머리 관찰·초당 확인·감점과 추적 누락 3초 집계도 정지한다. 확인 창 시간을 전 구간 채점과 누락 경과 시간에 포함하지 않는 예외다. 취소하면 이전 단계·답변·점수·타이머 상태를 복원하고 이후 6.52의 응답 타이머 보정을 적용해 재개하며 멈춘 동안의 자료·시간을 소급 반영하지 않는다. 상세 범위는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.29를 따른다.

실제 AI·음성·카메라 작업의 정지/보류/취소·재개 방법, 재생 위치와 동시 사건 순서는 미정이다. 사용자 중도·자동 무응답 종료의 무평가는 이후 6.51과 같이 지정받았다. 조기 종료 이력 미저장은 이후 6.52를 따르며 조기 종료 후 시작 화면 복귀는 이후 6.53을 따른다. 이번 문서 변경에서는 앱 소스·시험을 수정하지 않았다.

### 6.51 사용자 중도·자동 무응답 종료의 무평가 지정 (2026-11-05)
사용자가 수동 중도 종료의 평가 생략을 승인하고 자동 무응답 종료도 평가·점수 산출 없이 끝내도록 지정했다. 새 질문·이어서 말하기·최종 평가 중 답변 재개 후의 두 번째 무응답 모두 포함하며 완료 문항 수와 관계없다. 항목별/종합점수와 결과 점수 표시는 없고 0점으로 대체하지 않는다. 이전 완료 비율 감점·추가 5점·완료 0개 시 종합 0점 규칙은 대체해 적용을 중단한다. 정상 완료의 가중치·배점·평균·표시는 유지한다. 상세 범위는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.30을 따른다.

이 승인 기록 당시에는 기존 평가·감점 구현과 차이가 있었다. 이후 사용자가 코드 변경도 승인했으며 최신 반영 현황은 아래 무평가 종료 Core 구현 절을 따른다. 조기 종료 기록 미저장은 이후 6.52와 같이 지정받았으며 조기 종료 후 시작 화면 복귀는 이후 6.53을 따른다. 이번 설계 작업에서는 소스·시험을 수정하지 않았다.

### 6.52 조기 종료 이력 미저장·재개 잔여 시간 보정 지정 (2026-11-05)
사용자가 사용자 중도 종료·자동 무응답 종료 모두 스크립트·기본정보를 이력에 저장하지 않도록 지정했다. 정상 완료 이력의 범위는 유지하며 확인 창 취소 후 정상 완료한 면접은 정상 이력 규칙을 따른다. 상세 범위는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.31을 따른다.

확인 창 취소 후 첫 단어 대기 7초와 답변 무음 3초의 잔여 시간이 1초 미만이면 정확히 1초를 더하고, 1초 이상이면 그대로 재개하도록 지정받았다. 7초 중 2초 경과 시 5초 유지, 6.1초 경과 시 0.9초에 1초를 더해 1.9초다. 추적 누락 3초와 움직임 확인 주기는 추가 보정하지 않는다. 표시 시간 제외·단계/답변/점수 보존은 유지하며 상세 범위는 같은 문서 4.32를 따른다.

0초 도달과 확인 창 표시의 사건 순서·실제 시간 예약/재개 API·임시 자료 해제는 미정이다. 이번 설계 변경에서는 소스·시험을 수정하지 않았다.

### 6.53 조기 종료 후 시작 화면 복귀 승인 (2026-11-05)
사용자가 사용자 중도 종료·자동 무응답 종료 후 회사명·업종·직무·면접 종류를 입력하는 시작 화면으로 돌아가는 흐름을 승인했다. 평가·점수 산출·결과 점수 표시·이력 저장은 없으며 정상 완료 흐름은 유지한다. 종료 확인 창 취소는 화면 복귀가 아니라 기존 면접 재개다. 상세 범위는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.33을 따른다.

직전 네 입력값 유지는 이후 6.54와 같이 승인받았다. 종료 사유 안내·일본어 문구·전환 방식과 새 실행의 구체적인 상태 표현은 미정이다. 이번 설계 작업에서는 앱 소스·시험을 수정하거나 화면 이동을 구현하지 않았다.

### 6.54 시작 화면 복귀 시 입력값 유지 승인 (2026-11-05)
사용자가 사용자 중도·자동 무응답 종료 후 시작 화면에 직전 회사명·업종·직무·면접 종류를 유지하는 방식을 승인했다. 값을 다시 쓰지 않고 같은 조건을 사용하거나 필요한 항목만 수정할 수 있다. 입력 상태 보존과 조기 종료 이력 저장은 구분하며, 무평가·점수 미산출·이력 미저장과 새 면접 시작 규칙은 유지한다. 상세 범위는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.34를 따른다.

앱을 완전히 종료했다가 다시 열어도 마지막 네 입력값을 복원하는 방식은 이후 6.55와 같이 승인받았다. 상태 구조·저장 기술·초기화와 화면 전환의 구체적인 구현은 미정이다. 이번 설계 작업에서는 앱 소스·시험을 수정하지 않았다.

### 6.55 앱 재실행 후 마지막 입력값 복원 승인 (2026-11-05)
사용자가 마지막 회사명·업종·직무·면접 종류를 기기 내부에 별도로 보관하고 앱을 완전히 종료한 뒤 다시 열어도 시작 화면에 복원하는 방식을 승인했다. 이전 답변·진행 상태의 복원으로 확대하지 않으며 조기 종료 이력 미저장과 기존 정상 완료 흐름은 유지한다. 상세 범위는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.35를 따른다.

저장 시점은 이후 6.56과 같이 실제 면접 시작 때로 지정됐다. 저장 기술·구조·초기화·백업·실제 복원 처리는 미정이다. 이번 설계 작업에서는 앱 소스·시험을 수정하지 않았다.

### 6.56 면접 실제 시작 시 입력값 저장 지정 (2026-11-05)
사용자는 입력값 변경 때마다 저장하는 제안을 거절하고, 모의면접이 실제로 시작됐을 때만 회사명·업종·직무·면접 종류를 저장하도록 지정했다. 입력 수정·준비 화면 진입만으로 저장값을 갱신하지 않으며, 면접을 시작하지 않고 앱을 완전히 종료하면 재실행 시 직전 저장값을 복원한다. 상세 범위는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.36을 따른다.

네 입력값 저장과 정상 완료 이력 저장은 구분하며 조기 종료 이력 미저장은 유지한다. 실제 시작 순간의 구체적인 정의는 같은 문서 4.37의 미승인 제안이며, 저장 기술·구조·첫 저장 전 기본값·초기화·백업·오류 처리는 미정이다. 이번 설계 작업에서는 앱 소스·시험을 수정하거나 실제 저장·복원을 구현·시험하지 않았다.

## 임시 소스 구현 현황

사용자가 Xcode 프로젝트 생성 전 `ios_temp/`에 옮겨 쓸 수 있는 Swift 소스 작성을 요청했다. 별도 제품 패키지는 만들지 않는다. 사용자 계획은 저장소 루트의 `FirstStepToCareer/`에 Xcode 프로젝트를 생성한 뒤 바깥 폴더명을 `ios/`로 바꾸는 것이다. 실제 프로젝트 생성·이동은 사용자가 수행한다.

현재 질문 설정·답변 및 종합점수 계산·한 자리 표시의 소스와 시험을 작성했다. 점수는 정수 분자·분모를 유지하며 평균·가중치·감점 중간에 반올림하지 않는다. 완료 0개는 평균 자료 없이 종합점수 0을 반환하며 화면 표시는 결정하지 않는다. 움직임 구간·누적 감점·공동 제외 및 연속 3초 추적 누락 규칙도 합성 입력으로 구현·검증했다. 화면 위치와 정상 추적 여부·누락 시각은 호출자가 제공하며 실제 ARKit 판정은 구현하지 않는다. 관찰 자료가 아직 없는 상태는 평가 제외·100점과 구분해 별도 상태로 반환한다.

위 완료 0개 시 0점 반환은 이전 구현 기록이다. 추가 승인에 따라 최신 6.51의 사용자/무응답 무평가 종료와 채점 API를 수정했으며 현재 동작은 아래 무평가 종료 구현 절을 따른다.

면접 진행도 시간순 사건·작업 지시로 구현했다. 실제 STT 시작 확인부터 7초를 재고 새 발화 후의 별도 무음 사건으로 3초를 잰다. 이어 말하기는 준비/재생/평가 작업을 구분해 취소 지시를 만들고 취소된 결과를 무시한다. 원문·추가 발화는 조각 순서로 유지하며 움직임은 결과 표시 직전 사건까지 반영한다. 승인되지 않은 재개 시점·관찰 자료 없는 결과는 승인 필요 오류로 구분한다. 화면·SwiftData·AI·음성·ARKit 연결과 기존 미정 정책은 포함하지 않는다. 상세 범위와 남은 결정은 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)를 따른다.

## 종료 확인 창 정지·취소 재개 Core 구현

`InterviewSession`은 확인 창 실제 표시·취소 사건을 받아 이전 진행 상태를 유지한다. 표시 시간은 별도로 누적하고 이를 뺀 면접 시간을 무응답 7초·무음 3초·추적 누락 3초에 전달한다. 표시 중에는 자료와 결과를 적용하지 않는다. 취소 시 1초 미만의 응답 잔여 시간에만 1초를 더하는 승인 규칙도 반영했다. 정확한 만료와 창 표시의 순서는 승인 필요 경계로 구분한다. 실제 작업 연결부로 중단·재개 지시를 반환하며 재개 시 음성/AI 작업 번호와 움직임 관찰 번호를 갱신해 이전 자료를 구분한다. 대응 시험을 포함한 시험 함수 45개와 iOS 26 소스 검사가 통과했다.

화면과 실제 장치·모델 작업 중단/재개는 구현하지 않았다. 재생 위치·동시 사건 순서·종료 확정 뒤의 무평가 종료 코드 변경은 별도 범위다. 위 6.51의 이전 평가/감점 구현 차이는 이 작업에서 임의로 바꾸지 않았다.


## 무평가 종료 Core 구현

추가 승인에 따라 두 번째 무응답은 평가 요청 없이 `endedWithoutScore`로 끝낸다. `outcome`은 진행 중·정상 완료 점수·무평가 종료 사유를 구분하고 `OverallScoring.calculate`는 조기 종료에서 평균·점수 계산 없이 `nil`을 반환한다. 종료 후 이전 AI·음성·관찰·시간 사건은 무시하며 `isEligibleForHistory`는 정상 결과 확정 때만 참이다. 완료 수 0/1/3/5·최종 답변 재개 실패·움직임 포함/제외 및 정상 완료 채점을 검증했다. iOS 26 양쪽 기본 설정 소스 검사와 시험 함수 48개·매개변수 사례가 통과했다. `.exitConfirmationConfirmed`는 표시 중인 창 번호가 일치할 때만 무평가 종료로 연결하며 이전/잘못된 창 번호는 무시한다. 9개 단계의 확인 종료와 취소 후 정상 완료 이력 대상을 검증했다. 실제 장치 중단·저장·화면 이동은 미구현이다.

## 검증 모델 파일 보관 요청

사용자가 승인된 첫 검증 모델을 저장소의 `llm/` 아래에 다운로드하도록 요청했다. 제작사 원본 `LiquidAI/LFM2.5-1.2B-JP-202606`의 지정 리비전 파일 10개를 다운로드하고 공식 해시·파일 구조 검증을 완료했다. 원본 모델 폴더는 Git에서 제외하고 출처와 검증 기록만 추적한다. 자세한 상태는 [OPERATIONS.md](OPERATIONS.md)의 검증 모델 로컬 다운로드 절을 따른다. 이번 원본 보관으로 별도 압축 형식·제품 최종 모델·앱 배포 방식·실행 도구 버전을 결정하지 않았으며 앱 소스 변경이나 모델 실행도 하지 않았다.
