# 임시 면접 핵심 소스 구현 계획

> 2026-11-05 사용자가 `ios_temp/`에 나중에 iOS 프로젝트로 옮길 Swift 소스 작성을 요청했다. 앞선 별도 제품 패키지 생성안은 사용하지 않는다. 기존 승인된 계산·진행 규칙과 그 독립 시험을 구현하며 실제 화면·저장·AI·음성·추적의 미정 사항은 결정하지 않는다.

## 1. 경로와 인계 범위

- 사용자 예정 작업: 저장소 루트 `FirstStepToCareer/`에 Xcode 프로젝트 생성 → 바깥 폴더명을 `ios/`로 변경.
- 에이전트 작업: `ios_temp/Sources/Core/`에 앱 대상으로 옮길 소스, `ios_temp/Tests/Core/`에 단위 시험 대상으로 옮길 Swift Testing 시험 작성.
- 프로젝트·앱 시작점·화면·서명·앱 식별자는 생성하지 않는다. 앱 모듈 이름이 `FirstStepToCareer`와 다르면 시험의 import만 맞춘다.
- 검증용 패키지는 스크립트 실행 시 임시 경로에만 만든다. 제품 패키지·외부 의존성을 추가하지 않는다.
- 상세 이전 순서는 [INTEGRATION.md](../../ios_temp/INTEGRATION.md)를 따른다.

## 2. 작업·커밋 단위

각 행에 해당 구현·시험·TASK.md 상태와 관련 문서를 함께 넣는다. 검증 성공 후 커밋하고 즉시 푸시하며 성공을 확인한 뒤 다음 단위를 진행한다.

## 최신 종료 정책 반영 현황

[SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.30에 따라 사용자 중도 종료·자동 무응답 종료는 평가·점수 없이 끝낸다. 아래 완료 비율·추가 5점·완료 0개 종합 0점은 이전 구현 기록이며 현재 제품 정책으로 사용하지 않는다. `InterviewSession`은 두 번째 무응답 후 평가를 요청하지 않으며 `OverallScoring`은 조기 종료에서 평균·점수 계산 없이 `nil`을 반환한다.

추가 승인에 따라 점수 없는 종료 상태·두 종류 무응답·늦은 결과 무시·정상 완료 채점을 구현·검증했다. 창 번호가 일치하는 사용자 종료 확정도 같은 무평가 종료로 연결했다. `outcome`으로 진행 중·정상 완료·무평가 종료를 구분하고 `isEligibleForHistory`는 정상 완료만 허용한다. 조기 종료 스크립트·기본정보는 이력에 저장하지 않으며 조기 종료 후에는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.33에 따라 시작 조건 입력 화면으로 돌아가야 한다. 실제 저장·자료 정리·화면 이동은 미구현이며 복귀 시 네 입력값 유지는 최신 4.34의 승인 규칙이며, 앱 재실행 후 네 입력값 복원도 4.35와 같이 승인받았다. 저장 기술·시점·상태 구조·안내 문구·전환 구현은 미정이다.

## 3. 구현 방식과 검증

### 종료 확인 중 일시정지·취소 후 재개 구현 범위

사용자가 기존 제안의 구현과 이어지는 MLX 버전·모델 파일 형식 조사를 승인했다. `InterviewEvent.swift`, `InterviewSession.swift`와 대응 시험을 수정한다. 확인 창이 실제로 표시된 사건에서 이전 단계·답변·점수·남은 시간을 보존하고, 표시 중의 경과 시간을 제외한 면접 시간으로 무음·무응답·추적 누락을 계산한다. 취소 사건에서 이 상태를 재개하며, 멈춤 중 전달된 결과는 보관하거나 소급 반영하지 않는다. 최신 승인에 따라 응답 타이머의 잔여 시간이 1초 미만이면 1초를 더하고 추적 시계에는 더하지 않는다. 응답 만료와 창 표시의 정확한 동시 시각은 승인 필요 경계로 둔다.

실제 작업 연결부에는 중단·재개 지시만 반환한다. 취소 후 작업 번호와 움직임 관찰 번호를 새로 발급해 이전 음성·AI·관찰 결과를 구분한다. 실제 작업 중단·보류·재실행의 방법과 음성 재생 위치·화면·동시 사건 우선순위는 정하지 않는다. 정상 시간과 일시정지 시간이 섞이는 오류, 이전 결과의 재적용을 중점 시험한다. 새 외부 라이브러리를 추가하지 않는다.

Core 구현·연결 검증을 완료했다. 질문 준비/재생·인식 시작/대기·답변·재질문 준비/재생·평가·결과 표시 대기의 9단계에서 표시 중 사건 차단·취소 후 새 번호 재개를 시험했다. 응답 0.9초/정확히 1초 경계·반복/추가 답변·추적 시계에 보정 미적용·0초 확인 창도 검증했다. iOS 26 기본/MainActor 소스 검사와 시험 함수 45개·매개변수 사례가 통과했다.

사용자가 추가 질문에 ‘점수 없이 끝나도록 변경’을 승인했다. 무응답은 7초 재질문·다시 7초의 시간 기준을 유지하되 평가를 요청하지 않는 종료 상태로 전환한다. `OverallScoring.calculate`는 조기 종료에 점수 없음(`nil`)을 반환하고 정상 완료에만 계산한다. 사용자 종료 확인은 창 번호가 일치할 때 같은 무평가 종료로 연결하며, 취소는 기존 정지·재개 처리를 유지한다. 완료 여부를 별도 종료 결과로 표현해 진행 중의 점수 없음과 구분하고, 종료 후 이전 평가·관찰 자료를 적용하지 않는다. 조기 종료는 이력 저장 대상에서도 제외하지만 실제 저장소·자료 정리·이동 화면은 구현하지 않는다.

MLX 조사는 버전·의존 도구·파일 형식·호환성 근거와 제안까지 수행하며 설치·모델 형식 변경·추가 모델 다운로드·모델 실행은 하지 않는다.

조사를 완료하고 [MLX_RESEARCH.md](MLX_RESEARCH.md)에 공식 근거·고정 후보·미검증 범위·승인 후 작업 순서를 정리했다. 제안은 MLX Swift LM 3.32.3·내부 계산 도구 0.32.3·swift-transformers 1.4.0·약 696.9MB의 공식 MLX 4비트 파일이다. iOS 26에서는 기본 FoundationModels 연결 옵션을 끄는 안을 제안하며 실제 설정·빌드는 하지 않았다. 추가 의존성·모델 다운로드와 시험 조건은 승인 후 확정한다.

- Swift 6 언어 모드에서 검증한다. 점수는 정수 분자·분모로 표현하고 표시할 때만 반올림한다. 문항 수·배점·감점 단위는 정수로 관리한다.
- 움직임의 시험 위치는 화면 폭·높이를 각각 0~1로 나타낸 값이다. 실제 ARKit 좌표의 화면 변환을 뜻하지 않는다.
- 면접 코드는 사건을 전달받아 진행 단계와 필요한 작업 지시를 만든다. 새 단어 감지·무음 시작·STT 시작·작업 완료·시간 진행을 시험에서 전달한다. 실제 일본어 단어 판별·무음 검출은 구현하지 않는다.
- 이어 말하기로 취소한 작업은 식별 값을 바꾸어 늦게 도착한 이전 결과를 반영하지 않도록 한다. 실제 AI·음성 작업 취소는 후속 연결 대상이다.
- 실제 질문 생성·답변 평가는 연결하지 않는다. 시험에서 세부 점수를 입력하며, 계산 시험 성공을 AI 평가 품질 검증으로 보고하지 않는다.
- 최종 질문과 기존·추가 발화의 순서는 메모리에서 보존한다. 문자열을 공백·줄바꿈으로 어떻게 합칠지와 SwiftData 저장 구조·시점은 결정하지 않는다.
- 경계값과 실패 사례: 질문 수 2/3/5/7/8, 완료 문항 0개·중복 집계 방지, 무응답 7초·답변 종료 3초의 직전/도달/직후, 화면 구간의 선·모서리·바로 안팎, 누적 감점 하한, 취소된 결과의 늦은 도착.
- 이전 구현 계산 시험 예시(48점/43점의 조기 종료 예시는 최신 정책에 적용 중단): 다섯 항목 78.5점, 움직임 제외 80.625점→80.6, 5문 중 3문 완료·품질 80점일 때 48점/이어 말하기 실패 43점, 정수 80→80.0, 82.35→82.4.
- 동시 사건의 우선순위·카운트다운 중 이어 말하기·결과 표시 후 재개·관찰 자료가 전혀 없는 경우는 제품 동작으로 확정하지 않는다. 필요한 경우 승인 경계로 표시한다.

## 4. 검증 환경과 한계

Xcode 27.2(27B52), Swift 6.4.2, SDK 27.2 환경에서 `bash ios_temp/Scripts/verify.sh`로 iOS 26 배포 대상 소스 검사와 Mac 단위 시험을 수행한다. 임시 패키지의 Mac 대상은 개발용 시험만을 위한 것이며 앱 출시 플랫폼은 iOS만 유지한다. 기본 설정·MainActor 기본 설정의 iOS 26 소스 검사와 Swift Testing 시험 함수 48개·매개변수 사례가 통과했다. 두 종류 무응답의 무평가 종료, 완료 수 0/1/3/5의 점수 미생성, 마지막 답변 재개 실패 후 이전 평가·관찰 폐기, 9개 단계의 사용자 종료 확정과 잘못된/이전 창 번호 거부·취소 후 정상 완료 이력 대상을 포함한다. 실제 iOS 앱 링크·설치·실행·UI·성능 시험은 사용자 프로젝트 생성 후 수행한다.

## 5. 별도 승인 대상으로 남기는 사항

- 화면 분리·탐색·배치·일본어 문구·타이머 모양·제외 안내와 복수 사유 표시.
- SwiftData 엔티티·필드·관계·식별자, 정상 완료 저장 시점·보관/백업/복구·같은 시작 일시 정렬.
- MLX Swift LM 버전·연동 설정, 모델 파일·배포/다운로드, 질문·평가 지시문·출력 형식·오류 처리·품질과 성능 합격 기준, 제품 최종 모델·서버·외부 전송 여부.
- STT 단어·중간/확정 결과 반영·무음 검출·권한/오류·언어 모델 설치, TTS 목소리·속도·오디오 제어.
- 실제 시선·머리 기준점·좌표 변환·보정·거리·정상 자료 품질·누락/회복 감지·시간 측정·관찰 시각·제외 후 카메라 운용. 승인된 추적 제외 규칙은 합성 입력으로만 시험한다.
- 설정 저장·잠금 표시·비활성 상태 카메라 동작, 동시 사건 우선순위, 별도 일시정지 기능·입력값의 저장 기술/시점/초기화·취업활동 관리 범위. 사용자 종료 전 확인·취소와 확인 창 표시 중 면접/AI/음성/타이머/움직임 관찰·채점/추적 누락 집계 모두 정지·취소 후 상태를 유지한 재개는 [SITE_MAP.md](../ui-design/SITE_MAP.md)의 4.28·4.29를 따른다. 이는 후속 연결에 반영할 승인 설계이며 이번 문서 갱신에서 새 재개 API는 정하지 않는다. 최신 승인인 면접 시작 시의 공동 설정 적용·면접 중 변경 금지는 유지하며 설정 변경 API를 추가하지 않는다. 조기 종료 이력 미저장은 4.31을 따르고, 재개 시 첫 단어7초·답변무음3초의 잔여가 1초 미만이면 1초 추가하는 보정은 4.32를 따른다. 추적 누락·관찰 주기는 보정하지 않는다. 구현·시험 범위를 확정할 때 이 최신 설계를 기준으로 한다.

점수·음성·영상·움직임 원본·제외 사유를 과거 이력에 저장하는 기능을 추가하지 않는다. 보유 iPhone 14 Plus의 OS·연결 상태와 iPhone 13 지원·성능은 별도 실기기 검증 대상이다.
