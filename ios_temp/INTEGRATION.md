# Xcode 프로젝트로 소스 옮기기

`ios_temp/`는 사용자가 Xcode 프로젝트를 만들기 전 소스와 시험을 보관하는 임시 폴더다. Xcode 프로젝트·앱 시작점(`@main`)·화면은 포함하지 않는다.

## 폴더 구성

- `Sources/Core/`: 앱에 넣을 Swift 소스. 외부 라이브러리나 별도 패키지에 의존하지 않는다.
- `Tests/Core/`: Swift Testing 단위·연결 시험. 앱 소스와 다른 시험 대상에 넣는다.
- `Scripts/verify.sh`: Xcode 프로젝트 생성 전 Mac에서 같은 소스를 시험하는 개발용 도구.

## 옮기는 순서

1. 사용자가 저장소 루트의 `FirstStepToCareer/`에 Swift·SwiftUI iOS 프로젝트를 만든다. 최소 iOS 버전은 승인된 26.0으로 설정하고 단위 시험 대상을 포함한다. 앱 식별자·서명 등은 사용자 설정을 따른다.
2. 계획한 대로 바깥쪽 `FirstStepToCareer/` 폴더 이름을 `ios/`로 바꾼다. 안의 앱 소스 폴더와 앱 대상 이름은 Xcode에서 생성한 것을 사용한다. 이름 변경 후 `.xcodeproj`를 다시 열어 경로를 확인한다.
3. `Sources/Core/`를 `ios/` 안의 **앱 소스 폴더**로 복사하고, 그 Swift 파일들이 앱 대상에 포함됐는지 Xcode에서 확인한다. `Core/` 안에 시작점은 없으므로 Xcode가 만든 앱 시작 파일을 그대로 사용한다.
4. `Tests/Core/`의 Swift 파일들을 **단위 시험 폴더**로 복사한다. 앱 대상에는 넣지 않는다. 시험 파일의 `@testable import FirstStepToCareer`는 앱의 모듈 이름을 뜻한다. 이름이 다르면 이 부분만 실제 이름으로 바꾼다.
5. 앱 대상과 시험 대상에 사용한 Swift 소스는 Swift 6 언어 모드로 검증했다. Xcode 설정의 언어 모드를 확인하고 단위 시험을 실행한다. 이 시험에는 마이크·카메라·AI 모델 설치가 필요하지 않다. 핵심 값 형식은 `nonisolated`로 선언해 Xcode의 기본 MainActor 설정에도 영향을 받지 않도록 했다. 검증한 도구는 Swift 6.4.2다.
6. Xcode에서의 빌드·시험 확인 후 임시 폴더 정리는 별도로 진행한다. 현재 작업에서는 사용자 프로젝트 생성·이름 변경·기존 파일 삭제를 수행하지 않는다.

앱 소스 폴더에 임시 폴더 전체를 넣으면 시험·스크립트·안내 문서까지 앱 대상으로 들어갈 수 있다. `Sources/Core/`와 `Tests/Core/`를 각 대상에 나누어 넣는다. 대상은 Xcode가 함께 빌드할 파일을 묶는 단위다.

## 프로젝트 생성 전 검증

저장소 루트에서 다음 명령을 실행한다.

```bash
bash ios_temp/Scripts/verify.sh
```

스크립트는 임시 디렉터리에 소스·시험을 복사하고, 그곳에서만 검증용 Swift 패키지를 만들어 시험한다. 저장소에는 `Package.swift`나 빌드 결과를 만들지 않고 외부 패키지도 받지 않는다. 임시 경로는 실행할 때 출력하며 자동 삭제하지 않는다. `--disable-sandbox`는 Swift 패키지 빌드 도구의 중첩 격리를 끄는 옵션이며 앱의 보안 설정을 바꾸지 않는다.

Mac에서의 핵심 규칙 검증은 실제 iOS 앱·기기 검증과 구분한다. 화면, SwiftData 저장, LLM·음성·ARKit 연결과 미정인 정책은 포함하지 않는다.

## 연결할 때 지킬 입력 조건

`InterviewSession`은 현재 진행 단계를 보관하며 `handle(_:at:)`에 사건과 시간을 전달하면 필요한 작업 목록을 반환한다. 이 목록은 작업 지시이며 실제 AI 생성·음성 재생·마이크 시작을 실행하지 않는다. 별도 연결 코드는 아직 작성하지 않았다.

1. `.start`가 반환한 질문 준비 지시의 작업 번호로 `.questionPrepared`를 전달한다. 질문 재생 지시가 나오면 재생 완료 후 그 번호로 `.playbackFinished`를 전달한다.
2. 음성 인식 시작 지시 후 실제 인식이 시작됐을 때 `.recognitionStarted`를 전달한다. 이 시각부터 첫 단어 대기 7초를 센다.
3. **새 발화의 단어가 확인된 새 조각**만 `.newSpeechSegment`로 전달한다. 이 사건은 단어 판별을 수행하지 않는다. STT의 전체 중간 결과를 매번 넣으면 원문이 중복되므로 현재 연결용으로 사용하지 않는다. 기존 답변은 새 발화 사건으로 다시 보내지 않는다.
4. 실제 발화 활동과 무음 시작은 `.speechActivity`·`.silenceBegan`으로 별도 전달한다. 단어가 없었다는 이유만으로 무음으로 판단하지 않는다. 답변 시작 뒤 연속 무음 3초가 되어야 답변이 완료된다. 카운트다운의 남은 값은 `silenceCountdownRemaining(at:)`로 읽을 수 있다. 애니메이션은 구현하지 않았다.
5. 시간 진행은 `.timeAdvanced`로 전달한다. 새 발화 시작과 종료의 시간 기준은 각각 인식 시작·실제 무음 시작이다. 사건은 같은 기준의 단조 증가하는 `Duration` 시각으로 전달한다. 실제 시계·예약 방법·동시 사건 우선순위는 후속 결정이다.
6. 이어 말하기는 다음 질문 준비·재생, 정상 완료 후 최종 평가 중에 처리한다. 반환된 취소 지시는 연결 코드가 실제 작업을 취소할 때 사용한다. 이후 도착한 이전 작업 번호의 결과는 무시한다. 카운트다운 중·결과 표시 뒤·무응답 조기 종료 뒤의 재개는 승인 필요 오류로 구분한다.
7. 평가 완료 사건에는 완료한 문항들의 점수만 문항별 한 번씩 전달한다. 표시 직전 `.resultsWillDisplay`에서 마지막 움직임 점수를 포함해 종합점수를 계산한다. 움직임은 그 시점 직전까지 반영한다. `completedTurns`와 전체 `turns`는 구분되며, 조기 종료 이력 저장 범위는 결정하지 않았다.

`RubricRatings`는 아래 순서의 정수 4개를 받는다. 각 값은 0·1·2다. 실제 답변 평가 방법은 미정이며 시험에서는 값을 직접 준다.

| 항목 | 네 값의 순서 |
|---|---|
| 구성 | 핵심 제시·정보 순서·내용 집중·마무리 |
| 논리력 | 근거 제시·근거와 결론의 연결·같은 답변 안의 일관성·비약 억제 |
| 현실성 | 구체성·실행 가능성·직무/상황 적합성·결과의 개연성 |

움직임 확인 사건은 초당 한 건씩, 정상 여부 변경은 `.trackingAvailability`로 발생 시각에 전달하는 구조다. 정상 자료 판별·누락 시각 감지·좌표 보정·초당 예약은 미정이다. `nil` 확인은 해당 항목 감점만 건너뛰며 누락 시작 시각을 추정하지 않는다. 관찰 자료를 전혀 받지 못한 경우는 100점이나 평가 제외로 대신하지 않고 승인 필요 경계로 남긴다. 제외 사유 집합은 표시 우선순위를 뜻하지 않는다.

세션 생성 시 받는 질문 설정과 제외 조건은 독립 시험의 입력이다. 최신 승인에 따라 실제 연결 시에는 면접 시작 시의 공동 채점 설정을 전달하며, 현재 세션에는 설정을 바꾸는 기능을 제공하지 않는다. 저장 방식·잠금 표시·사용자 종료 절차는 미정이다. 답변 조각은 순서대로 보존하며 화면·저장용 문자열의 결합 방식도 정하지 않았다.
