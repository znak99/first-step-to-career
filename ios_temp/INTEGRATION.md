# Xcode 프로젝트로 소스 옮기기

`ios_temp/`는 사용자가 Xcode 프로젝트를 만들기 전 소스와 시험을 보관하는 임시 폴더다. Xcode 프로젝트·앱 시작점(`@main`)·화면은 포함하지 않는다.

## 폴더 구성

- `Sources/Core/`: 앱에 넣을 Swift 소스. 외부 라이브러리나 별도 패키지에 의존하지 않는다.
- `Tests/Core/`: Swift Testing 단위·연결 시험. 앱 소스와 다른 시험 대상에 넣는다.
- `Scripts/verify.sh`: Xcode 프로젝트 생성 전 Mac에서 같은 소스를 시험하는 개발용 도구.

## 옮기는 순서

1. 사용자가 저장소 루트의 `FirstStepToCareer/`에 Swift·SwiftUI iOS 프로젝트를 만든다. 최소 iOS 버전은 승인된 26.0으로 설정하고 단위 시험 대상을 포함한다. 앱 식별자·서명 등은 사용자 설정을 따른다.
2. 계획한 대로 바깥쪽 `FirstStepToCareer/` 폴더 이름을 `ios/`로 바꾼다. 안의 앱 소스 폴더와 앱 대상 이름은 Xcode에서 생성한 것을 사용한다. 이름 변경 후 `.xcodeproj`를 다시 열어 경로를 확인한다.
3. `Sources/Core/`를 `ios/` 안의 **앱 소스 폴더**로 복사하고, 그 Swift 파일들이 앱 대상에 포함됐는지 Xcode에서 확인한다. `Core/` 안에 시작점은 없으므로 Xcode가 만든 앱 시작 파일을 그대로 사용한다.
4. `Tests/Core/`의 Swift 파일들을 **단위 시험 폴더**로 복사한다. 앱 대상에는 넣지 않는다. 시험 파일의 `@testable import FirstStepToCareer`는 앱의 모듈 이름을 뜻한다. 이름이 다르면 이 부분만 실제 이름으로 바꾼다.
5. 앱 대상과 시험 대상에 사용한 Swift 소스는 Swift 6 언어 모드로 검증했다. Xcode 설정의 언어 모드를 확인하고 단위 시험을 실행한다. 이 시험에는 마이크·카메라·AI 모델 설치가 필요하지 않다. 핵심 값 형식은 `nonisolated`로 선언해 Xcode의 기본 MainActor 설정에도 영향을 받지 않도록 했다. 검증한 도구는 Swift 6.4.2다.
6. Xcode에서의 빌드·시험 확인 후 임시 폴더 정리는 별도로 진행한다. 현재 작업에서는 사용자 프로젝트 생성·이름 변경·기존 파일 삭제를 수행하지 않는다.

앱 소스 폴더에 임시 폴더 전체를 넣으면 시험·스크립트·안내 문서까지 앱 대상으로 들어갈 수 있다. `Sources/Core/`와 `Tests/Core/`를 각 대상에 나누어 넣는다. 대상은 Xcode가 함께 빌드할 파일을 묶는 단위다.

## 프로젝트 생성 전 검증

저장소 루트에서 다음 명령을 실행한다.

```bash
bash ios_temp/Scripts/verify.sh
```

스크립트는 임시 디렉터리에 소스·시험을 복사하고, 그곳에서만 검증용 Swift 패키지를 만들어 시험한다. 저장소에는 `Package.swift`나 빌드 결과를 만들지 않고 외부 패키지도 받지 않는다. 임시 경로는 실행할 때 출력하며 자동 삭제하지 않는다. `--disable-sandbox`는 Swift 패키지 빌드 도구의 중첩 격리를 끄는 옵션이며 앱의 보안 설정을 바꾸지 않는다.

Mac에서의 핵심 규칙 검증은 실제 iOS 앱·기기 검증과 구분한다. 화면, SwiftData 저장, LLM·음성·ARKit 연결과 미정인 정책은 포함하지 않는다.

## 점수 없는 종료의 연결

[SITE_MAP.md](../docs/ui-design/SITE_MAP.md)의 4.30을 반영해 두 번째 무응답은 평가 요청 없이 `.endedWithoutScore`로 끝난다. `.endWithoutScore` 지시는 연결부에서 남은 작업과 관찰을 중단할 때 사용한다. `outcome`은 진행 중의 `nil`, 정상 완료의 `.completed(scores)`, 점수 없는 종료의 `.endedWithoutScore(reason)`를 구분한다. `result`는 무평가 종료 시 `nil`이며 0점을 대신 넣지 않는다. 종료 후 도착한 사건은 무시한다.

`OverallScoring.calculate`는 조기 종료에 답변 평균·점수 계산 없이 `nil`을 반환하며 정상 완료에만 계산한다. `isEligibleForHistory`는 정상 결과가 확정된 경우만 참이다. 실제 SwiftData 저장·임시 자료 정리·화면 이동은 구현하지 않았다. 사용자 종료를 확인하면 현재 창 번호로 `.exitConfirmationConfirmed`를 전달한다. 번호가 일치할 때만 같은 무평가 종료로 끝나며 이전/잘못된 번호와 이미 닫힌 창의 확정은 무시한다. 취소 재개는 기존대로 동작한다. 현재 iOS 26 소스 검사와 시험 함수 48개·매개변수 사례가 통과했다.

## 연결할 때 지킬 입력 조건

### 종료 확인 창의 일시정지·취소 후 재개

확인 창이 실제로 표시된 시각에 `.exitConfirmationPresented`를 전달한다. Core는 이전 `phase`를 유지한 채 `exitConfirmationPause`에 확인 창 번호와 정지 시각을 보관하고 `.suspendInterviewWork`를 반환한다. 표시 중의 사건은 상태·답변·점수·타이머·관찰에 반영하지 않는다. 취소 후 창이 닫힌 시각에 그 번호로 `.exitConfirmationCancelled`를 전달하면 `.resumeInterviewWork`를 반환하며 표시 시간을 뺀 면접 시간으로 계속한다.

이 지시는 실제 AI·TTS·STT·카메라를 중단하거나 재생 위치를 복원하는 구현이 아니다. 실제 연결부가 모든 작업을 정지·재개하도록 구현해야 한다. 정지·보류·재실행 방법과 재생 위치·동시 사건 우선순위는 미정이다. 무평가 종료 변경도 추가 승인을 받아 사용자 확인 종료와 자동 무응답 종료 모두 Core에 반영했다.

재개할 때 `activeOperation`과 `observationOperation` 번호가 바뀐다. 음성·AI 결과에는 작업 시작 때 받은 번호를, `.movementCheck(operation:gaze:head:)`와 `.trackingAvailability(operation:gaze:head:)`에는 관찰 수집을 시작할 때 받은 번호를 넣는다. 결과를 전달하는 순간 현재 번호로 바꿔 붙이면 이전 자료를 구분할 수 없으므로 그렇게 사용하지 않는다. 이전 번호로 늦게 전달된 자료는 무시한다. 새 번호는 재개 지시에 들어 있다.

예를 들어 7초 중 2초가 지난 뒤 확인 창을 10초 표시했다 취소하면 5초가 남는다. 최신 승인에 따라 응답 타이머의 반올림 전 잔여 시간이 1초 미만이면 취소 시 정확히 1초를 더한다. 0.9초는 1.9초, 정확히 1초는 1초다. 추적 누락 시계에는 이 보정을 적용하지 않는다. 응답 제한 시각과 확인 창 표시가 정확히 겹치면 처리 우선순위를 임의로 선택하지 않고 승인 필요 경계를 반환한다. 추적 누락 3초의 집계도 같은 방법으로 표시 시간을 제외한다. 점수나 답변 조각을 초기화하지 않으며 확인 창을 여러 번 열어도 각 표시 시간만 제외한다.

이 동작은 9개 진행 단계에 대해 합성 사건으로 검증했다. 재개 지시의 새 작업 번호는 단순 표시값이 아니다. 이후 완료 통지를 받는 모든 작업에 일관되게 사용해야 하며, 이전 번호로 이미 대기 중인 통지를 새 번호로 바꿔 전달하지 않는다. 실제 작업을 어떤 방법으로 이어서 수행할지는 아직 연결하지 않았다.

`InterviewSession`은 현재 진행 단계를 보관하며 `handle(_:at:)`에 사건과 시간을 전달하면 필요한 작업 목록을 반환한다. 이 목록은 작업 지시이며 실제 AI 생성·음성 재생·마이크 시작을 실행하지 않는다. 별도 연결 코드는 아직 작성하지 않았다.

1. `.start`가 반환한 질문 준비 지시의 작업 번호로 `.questionPrepared`를 전달한다. 질문 재생 지시가 나오면 재생 완료 후 그 번호로 `.playbackFinished`를 전달한다.
2. 음성 인식 시작 지시 후 실제 인식이 시작됐을 때 `.recognitionStarted`를 전달한다. 이 시각부터 첫 단어 대기 7초를 센다.
3. **새 발화의 단어가 확인된 새 조각**만 `.newSpeechSegment`로 전달한다. 이 사건은 단어 판별을 수행하지 않는다. STT의 전체 중간 결과를 매번 넣으면 원문이 중복되므로 현재 연결용으로 사용하지 않는다. 기존 답변은 새 발화 사건으로 다시 보내지 않는다.
4. 실제 발화 활동과 무음 시작은 `.speechActivity`·`.silenceBegan`으로 별도 전달한다. 단어가 없었다는 이유만으로 무음으로 판단하지 않는다. 답변 시작 뒤 연속 무음 3초가 되어야 답변이 완료된다. 카운트다운의 남은 값은 `silenceCountdownRemaining(at:)`로 읽을 수 있다. 애니메이션은 구현하지 않았다.
5. 시간 진행은 `.timeAdvanced`로 전달한다. 새 발화 시작과 종료의 시간 기준은 각각 인식 시작·실제 무음 시작이다. 사건은 같은 기준의 단조 증가하는 `Duration` 시각으로 전달한다. 실제 시계·예약 방법·동시 사건 우선순위는 후속 결정이다.
6. 이어 말하기는 다음 질문 준비·재생, 정상 완료 후 최종 평가 중에 처리한다. 반환된 취소 지시는 연결 코드가 실제 작업을 취소할 때 사용한다. 이후 도착한 이전 작업 번호의 결과는 무시한다. 카운트다운 중·결과 표시 뒤의 재개는 승인 필요 오류로 구분한다. 무평가 종료 뒤에는 재개 요청도 무시한다.
7. 정상 완료의 평가 완료 사건에는 완료한 문항들의 점수만 문항별 한 번씩 전달한다. 표시 직전 `.resultsWillDisplay`에서 마지막 움직임 점수를 포함해 종합점수를 계산한다. 움직임은 그 시점 직전까지 반영한다. `completedTurns`와 전체 `turns`는 구분되며, 조기 종료 스크립트·기본정보는 이력에 저장하지 않는다.

`RubricRatings`는 아래 순서의 정수 4개를 받는다. 각 값은 0·1·2다. 실제 답변 평가 방법은 미정이며 시험에서는 값을 직접 준다.

| 항목 | 네 값의 순서 |
|---|---|
| 구성 | 핵심 제시·정보 순서·내용 집중·마무리 |
| 논리력 | 근거 제시·근거와 결론의 연결·같은 답변 안의 일관성·비약 억제 |
| 현실성 | 구체성·실행 가능성·직무/상황 적합성·결과의 개연성 |

움직임 확인 사건은 초당 한 건씩, 정상 여부 변경은 `.trackingAvailability`로 발생 시각에 전달하는 구조다. 정상 자료 판별·누락 시각 감지·좌표 보정·초당 예약은 미정이다. `nil` 확인은 해당 항목 감점만 건너뛰며 누락 시작 시각을 추정하지 않는다. 관찰 자료를 전혀 받지 못한 경우는 100점이나 평가 제외로 대신하지 않고 승인 필요 경계로 남긴다. 제외 사유 집합은 표시 우선순위를 뜻하지 않는다.

세션 생성 시 받는 질문 설정과 제외 조건은 독립 시험의 입력이다. 최신 승인에 따라 실제 연결 시에는 면접 시작 시의 공동 채점 설정을 전달하며, 현재 세션에는 설정을 바꾸는 기능을 제공하지 않는다. 저장 방식·잠금 표시·조기 종료 후 시작 조건 입력 화면으로 돌아가며 직전 회사명·업종·직무·면접 종류를 유지해야 한다. 이 네 입력값은 실제 면접 시작 때만 기기 내부에 별도 저장해 앱 재실행 후에도 복원해야 한다. 입력 수정·준비 화면 진입만으로 갱신하지 않으며 시작하지 않고 앱을 완전히 종료하면 직전 저장값을 복원한다. 실제 시작 순간·저장 기술·초기화·안내 문구·전환 방식은 미정이고 스크립트·기본정보의 이력 저장은 하지 않으며 평가·점수 미산출은 최신 승인 규칙이다. 사용자 종료 전 확인·취소와 확인 창 표시 중 전체 정지·취소 후 기존 상태를 유지한 재개는 [SITE_MAP.md](../docs/ui-design/SITE_MAP.md)의 4.28·4.29를 따른다. 정지 대상에는 AI·음성·응답 타이머·움직임 관찰/채점·추적 누락 집계가 모두 포함되며 실제 연결 API와 재개 방법은 별도 결정이 필요하다. 최신 4.32에 따라 취소 후 첫 단어7초·답변무음3초의 실제 잔여가 1초 미만이면 1초를 더한다. 0.9초는 1.9초이며 정확히 1초는 유지한다. 추적 누락3초·움직임 확인 주기는 추가 보정하지 않는다. 답변 조각은 순서대로 보존하며 화면·저장용 문자열의 결합 방식도 정하지 않았다.
