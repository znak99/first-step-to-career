# iOS 프로젝트 연결 안내

사용자가 생성한 `FirstStepToCareer.xcodeproj`에 기존 임시 소스를 이전했다. `ios_temp/`는 정리했다.

## 폴더와 대상

- `FirstStepToCareer/Views/`: 시작·4개 탭·하위 화면의 일본어 SwiftUI 화면과 이동.
- `FirstStepToCareer/Core/`: 기존 Swift 핵심 소스 7개. 앱 대상에 포함한다.
- `FirstStepToCareerTests/Core/`: 기존 Swift Testing 파일 6개. `FirstStepToCareerTests` 대상에만 포함한다.
- `FirstStepToCareerUITests/`: 화면 이동과 임시 설정 상태를 확인하는 별도 XCTest UI 시험 대상.
- `Scripts/verify.sh`: iOS 26 소스 검사·Mac 독립 시험 도구. 외부 패키지는 추가하지 않는다.
- `FirstStepToCareer.xcodeproj/`: 사용자가 생성한 Xcode 27.2 JSON 프로젝트. 앱 시작점·화면·서명 설정을 유지한다.

최소 iOS 26.0·Swift 6 언어 모드를 적용했다. 공유 스킴 `FirstStepToCareer`에 단위 시험과 UI 시험 대상을 연결했다. Xcode에서 이 프로젝트를 열고 실행 기기를 선택하면 앱을 빌드할 수 있으며, Product > Test로 기존 시험을 실행한다. 현재 화면은 스플래시·온보딩·4개 탭과 하위 화면의 기본 UI다. 실제 면접 진행·모델·음성·카메라·저장은 연결하지 않았다.

## 검증

저장소 루트에서 핵심 소스만 빠르게 검증한다.

```bash
bash ios/Scripts/verify.sh
```

실제 Xcode 시험은 설치된 시뮬레이터 이름 또는 ID를 지정한다. 아래 명령은 기존 단위 시험과 화면 이동 UI 시험을 함께 실행한다. 독립 검증 스크립트는 Core 시험만 실행한다.

```bash
xcodebuild test -project ios/FirstStepToCareer.xcodeproj -scheme FirstStepToCareer -configuration Debug -destination 'platform=iOS Simulator,name=iPhone 17' -derivedDataPath /tmp/first-step-ios-build CODE_SIGNING_ALLOWED=NO
```

검증 스크립트는 임시 폴더에만 Swift 패키지와 빌드 결과를 만든다. 실제 iPhone 서명·설치·성능/AI품질 검증은 별도다. Xcode가 `ios/.git`에 만든 초기 로컬 이력은 상위 저장소의 `.git/ios-created-repository-backup`에 보존했다. 앱 파일은 상위 저장소에서 일반 파일로 추적하며 사용자별 Xcode 상태는 커밋하지 않는다.

## 점수 없는 종료

무응답 두 번과 현재 확인 창 번호에 대한 사용자 종료 확정은 평가 요청 없이 `.endedWithoutScore`로 끝난다. `outcome`은 진행 중·정상 완료·무평가 종료를 구분하며 무평가 종료의 `result`는 `nil`이다. 종료 후 결과·관찰 사건은 무시한다. `isEligibleForHistory`는 정상 결과 확정에만 참이며 실제 저장·화면 이동은 미구현이다.

## 연결할 때 지킬 입력 조건

### 종료 확인 창의 일시정지·취소 후 재개

확인 창이 실제로 표시된 시각에 `.exitConfirmationPresented`를 전달한다. Core는 이전 `phase`를 유지한 채 `exitConfirmationPause`에 확인 창 번호와 정지 시각을 보관하고 `.suspendInterviewWork`를 반환한다. 표시 중의 사건은 상태·답변·점수·타이머·관찰에 반영하지 않는다. 취소 후 창이 닫힌 시각에 그 번호로 `.exitConfirmationCancelled`를 전달하면 `.resumeInterviewWork`를 반환하며 표시 시간을 뺀 면접 시간으로 계속한다.

이 지시는 실제 AI·TTS·STT·카메라를 중단하거나 재생 위치를 복원하는 구현이 아니다. 실제 연결부가 모든 작업을 정지·재개하도록 구현해야 한다. 정지·보류·재실행 방법과 재생 위치·동시 사건 우선순위는 미정이다. 무평가 종료 변경도 추가 승인을 받아 사용자 확인 종료와 자동 무응답 종료 모두 Core에 반영했다.

재개할 때 `activeOperation`과 `observationOperation` 번호가 바뀐다. 음성·AI 결과에는 작업 시작 때 받은 번호를, `.movementCheck(operation:gaze:head:)`와 `.trackingAvailability(operation:gaze:head:)`에는 관찰 수집을 시작할 때 받은 번호를 넣는다. 결과를 전달하는 순간 현재 번호로 바꿔 붙이면 이전 자료를 구분할 수 없으므로 그렇게 사용하지 않는다. 이전 번호로 늦게 전달된 자료는 무시한다. 새 번호는 재개 지시에 들어 있다.

예를 들어 7초 중 2초가 지난 뒤 확인 창을 10초 표시했다 취소하면 5초가 남는다. 최신 승인에 따라 응답 타이머의 반올림 전 잔여 시간이 1초 미만이면 취소 시 정확히 1초를 더한다. 0.9초는 1.9초, 정확히 1초는 1초다. 추적 누락 시계에는 이 보정을 적용하지 않는다. 응답 제한 시각과 확인 창 표시가 정확히 겹치면 처리 우선순위를 임의로 선택하지 않고 승인 필요 경계를 반환한다. 추적 누락 3초의 집계도 같은 방법으로 표시 시간을 제외한다. 점수나 답변 조각을 초기화하지 않으며 확인 창을 여러 번 열어도 각 표시 시간만 제외한다.

이 동작은 9개 진행 단계에 대해 합성 사건으로 검증했다. 재개 지시의 새 작업 번호는 단순 표시값이 아니다. 이후 완료 통지를 받는 모든 작업에 일관되게 사용해야 하며, 이전 번호로 이미 대기 중인 통지를 새 번호로 바꿔 전달하지 않는다. 실제 작업을 어떤 방법으로 이어서 수행할지는 아직 연결하지 않았다.

`InterviewSession`은 현재 진행 단계를 보관하며 `handle(_:at:)`에 사건과 시간을 전달하면 필요한 작업 목록을 반환한다. 이 목록은 작업 지시이며 실제 AI 생성·음성 재생·마이크 시작을 실행하지 않는다. 별도 연결 코드는 아직 작성하지 않았다.

1. `.start`가 반환한 질문 준비 지시의 작업 번호로 `.questionPrepared`를 전달한다. 질문 재생 지시가 나오면 재생 완료 후 그 번호로 `.playbackFinished`를 전달한다.
2. 음성 인식 시작 지시 후 실제 인식이 시작됐을 때 `.recognitionStarted`를 전달한다. 이 시각부터 첫 단어 대기 7초를 센다.
3. **새 발화의 단어가 확인된 새 조각**만 `.newSpeechSegment`로 전달한다. 이 사건은 단어 판별을 수행하지 않는다. STT의 전체 중간 결과를 매번 넣으면 원문이 중복되므로 현재 연결용으로 사용하지 않는다. 기존 답변은 새 발화 사건으로 다시 보내지 않는다.
4. 실제 발화 활동과 무음 시작은 `.speechActivity`·`.silenceBegan`으로 별도 전달한다. 단어가 없었다는 이유만으로 무음으로 판단하지 않는다. 답변 시작 뒤 연속 무음 3초가 되어야 답변이 완료된다. 카운트다운의 남은 값은 `silenceCountdownRemaining(at:)`로 읽을 수 있다. 애니메이션은 구현하지 않았다.
5. 시간 진행은 `.timeAdvanced`로 전달한다. 새 발화 시작과 종료의 시간 기준은 각각 인식 시작·실제 무음 시작이다. 사건은 같은 기준의 단조 증가하는 `Duration` 시각으로 전달한다. 실제 시계·예약 방법·동시 사건 우선순위는 후속 결정이다.
6. 이어 말하기는 다음 질문 준비·재생, 정상 완료 후 최종 평가 중에 처리한다. 반환된 취소 지시는 연결 코드가 실제 작업을 취소할 때 사용한다. 이후 도착한 이전 작업 번호의 결과는 무시한다. 카운트다운 중·결과 표시 뒤의 재개는 승인 필요 오류로 구분한다. 무평가 종료 뒤에는 재개 요청도 무시한다.
7. 정상 완료의 평가 완료 사건에는 완료한 문항들의 점수만 문항별 한 번씩 전달한다. 표시 직전 `.resultsWillDisplay`에서 마지막 움직임 점수를 포함해 종합점수를 계산한다. 움직임은 그 시점 직전까지 반영한다. `completedTurns`와 전체 `turns`는 구분되며, 조기 종료 스크립트·기본정보는 이력에 저장하지 않는다.

`RubricRatings`는 아래 순서의 정수 4개를 받는다. 각 값은 0·1·2다. 실제 답변 평가 방법은 미정이며 시험에서는 값을 직접 준다.

| 항목 | 네 값의 순서 |
|---|---|
| 구성 | 핵심 제시·정보 순서·내용 집중·마무리 |
| 논리력 | 근거 제시·근거와 결론의 연결·같은 답변 안의 일관성·비약 억제 |
| 현실성 | 구체성·실행 가능성·직무/상황 적합성·결과의 개연성 |

움직임 확인 사건은 초당 한 건씩, 정상 여부 변경은 `.trackingAvailability`로 발생 시각에 전달하는 구조다. 정상 자료 판별·누락 시각 감지·좌표 보정·초당 예약은 미정이다. `nil` 확인은 해당 항목 감점만 건너뛰며 누락 시작 시각을 추정하지 않는다. 관찰 자료를 전혀 받지 못한 경우는 100점이나 평가 제외로 대신하지 않고 승인 필요 경계로 남긴다. 제외 사유 집합은 표시 우선순위를 뜻하지 않는다.

세션 생성 시 받는 질문 설정과 제외 조건은 독립 시험의 입력이다. 최신 승인에 따라 실제 연결 시에는 면접 시작 시의 공동 채점 설정을 전달하며, 현재 세션에는 설정을 바꾸는 기능을 제공하지 않는다. 저장 방식·잠금 표시·조기 종료 후 시작 조건 입력 화면으로 돌아가며 직전 회사명·업종·직무·면접 종류를 유지해야 한다. 이 네 입력값은 실제 면접 시작 때만 기기 내부에 별도 저장해 앱 재실행 후에도 복원해야 한다. 입력 수정·준비 화면 진입만으로 갱신하지 않으며 시작하지 않고 앱을 완전히 종료하면 직전 저장값을 복원한다. 실제 시작 순간은 준비 화면 확인 후 첫 질문 생성을 시작하는 때로 승인받았다. 저장된 조건이 없는 첫 실행에서는 회사명·업종·직무를 미입력 상태로 둔다. 면접 종류의 초기 선택·항목별 필수 여부·입력/선택 방식은 미정이다. 네 입력값 저장과 기존 공동 설정 잠금·평가 가능한 움직임 관찰 시작에 같은 시점을 사용한다. 저장 기술·초기화·안내 문구·첫 질문 생성 실패 처리·전환 방식은 미정이고 스크립트·기본정보의 이력 저장은 하지 않으며 평가·점수 미산출은 최신 승인 규칙이다. 사용자 종료 전 확인·취소와 확인 창 표시 중 전체 정지·취소 후 기존 상태를 유지한 재개는 [SITE_MAP.md](../docs/ui-design/SITE_MAP.md)의 4.28·4.29를 따른다. 정지 대상에는 AI·음성·응답 타이머·움직임 관찰/채점·추적 누락 집계가 모두 포함되며 실제 연결 API와 재개 방법은 별도 결정이 필요하다. 최신 4.32에 따라 취소 후 첫 단어7초·답변무음3초의 실제 잔여가 1초 미만이면 1초를 더한다. 0.9초는 1.9초이며 정확히 1초는 유지한다. 추적 누락3초·움직임 확인 주기는 추가 보정하지 않는다. 답변 조각은 순서대로 보존하며 화면·저장용 문자열의 결합 방식도 정하지 않았다.

## 화면 뼈대와 실제 기능의 경계

`ContentView`와 `Views/`는 일본어 기본 화면 및 이동만 담당한다. 현재는 실행마다 스플래시 후 온보딩을 표시하고 완료 상태를 저장하지 않는다. 입력과 질문 수·움직임 설정은 실행 중에만 보관한다. 준비·면접 화면 이동으로 Core의 `.start`를 보내거나 장치 권한을 요청하지 않으며, 결과·과거 결과·일정·분석에 임의 데이터를 만들지 않는다. 실제 면접 시작·잠금·중도 종료·저장·복원은 후속 연결 시 위의 기존 계약을 따라야 한다.
