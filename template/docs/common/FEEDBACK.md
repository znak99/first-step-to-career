# FEEDBACK.md

Corrections the user has given to AI agents. Read this before any work, every session.

## Rules
- Write the essence of the correction, not the instance. Ask what general rule the user is actually pointing at, and write that rule. Leave out the feature, screen, or term the correction happened to be about.
  Example: the user says "로그인 기능을 설명할 때 세션이 뭔지 먼저 설명해". The essence is that the explanation assumed knowledge the user does not have.
  Write: `- [2026-10-13] Explain from zero: define every basic term before using it.`
  Do not write anything about login or sessions.
- One line per item: `- [YYYY-MM-DD] Imperative sentence.` Written in English even if the user spoke Korean. Keep the intent exact; keep it short.
- Never record the same point twice. Before adding, read the existing lines; if one already covers the point, add nothing.
- Append immediately when the user corrects you. Do not wait until the end of the session, and do not ask for approval.
- Never delete or reword existing items. If a later correction contradicts an earlier one, add the new line and mark the old one `(superseded)`.
- "Common" items come from the template and apply to every project. "This project" items are local. Local items that turn out to be generally useful get promoted to the template's Common list by the user.
